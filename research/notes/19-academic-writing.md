# 19 — Академическое письмо: курсовая, реферат, диплом, отчёт

Сценарий пользователя: «напиши курсовую по теме X, найди кучу источников, сложи их отдельно,
сделай Word-файл и **пиши вручную, по абзацам**, убери ИИ-паттерны, проверь юридическую
грамотность, работай, пока я не скажу „стоп“».

Это не «сгенерируй текст». Это **производственный процесс** из 9 этапов с артефактами.

## 1. Что реально требуется от курсовой (и чего не хватает у ChatGPT-однострочников)

| Требование | Почему ломает «просто сгенерируй» |
| --- | --- |
| Методичка конкретного вуза | В ней поля, шрифт, объём, структура, правила ссылок — часто **противоречат** ГОСТу |
| Структура: титул, содержание, введение (актуальность, объект/предмет, цель, задачи), 2–3 главы, заключение, список источников, приложения | Каждый раздел имеет свой жанр и клише |
| 25–40 источников, оформленных по ГОСТ Р 7.0.5-2008 / 7.1-2003 | Нужны **реально существующие** источники с выходными данными |
| Ссылки в тексте `[12, с. 45]` ↔ список литературы | Двусторонняя согласованность, нумерация по порядку упоминания |
| Оформление: TNR 14, интервал 1.5, поля 3/1.5/2/2, нумерация страниц со 2-й, рисунки/таблицы с подписями | Это работа со **стилями документа**, а не с текстом |
| Антиплагиат (вузовский) | Оригинальность = своя формулировка + корректные цитаты, а не «пересказ своими словами» одной статьи |
| «Убрать ИИ-паттерны» | Шаблонные вводные, симметричные абзацы, «важно отметить», отсутствие конкретики и цифр |
| Юридическая грамотность | Термины из НПА, актуальные редакции, отсутствие подмены понятий |

**Вывод для архитектуры:** нужен не «генератор текста», а **агент-редактор с документом как
объектом первого класса** (стили, сноски, нумерация, библиография) и с проверяемыми фактами.

## 2. Конвейер (9 этапов)

```
[1] Бриф        тема · вуз · дисциплина · объём · дедлайн · требования · нужен ли антиплагиат
[2] Методичка   найти PDF/страницу вуза, извлечь правила → checklist.md (проверяемый)
[3] План        структура глав/параграфов + тезис каждого абзаца → утверждение пользователем
[4] Источники   30–60 шт: поиск → отбор → карточки (bib) → скачивание PDF → конспект
[5] Каркас      DOCX со стилями (заголовки, TNR 14, 1.5, поля, нумерация) + титул по шаблону
[6] Текст       по абзацам: тезис → аргумент → ссылка → пример → вывод; запись в DOCX
[7] Проверки    ссылки↔список · цитаты · термины · стиль · читаемость · объём
[8] Полировка   «убрать ИИ-паттерны», выровнять жанр, юридическая вычитка
[9] Сдача       финальный DOCX + PDF + папка источников + отчёт «что где взято»
```

Ключевое: этапы 2, 3, 4 создают **артефакты в файлах** (`checklist.md`, `plan.md`,
`sources/*.pdf`, `sources/bib.json`). Если сессия упадёт, работа не потеряется.

## 3. «Ручная» запись в Word — как это делается правильно

Пользователь просит «вручную, а не сгенерировать Python Docs». Разница принципиальная:

| «Сгенерировать» | «Писать вручную» |
| --- | --- |
| один вызов → готовый docx из markdown | по абзацу: текст → стиль → сноска → сохранение |
| стили теряются, сноски отсутствуют | нативные стили Word, настоящие сноски, автосодержание |
| нет промежуточных сохранений | save каждые 3–5 абзацев + версии `v01.docx`, `v02.docx` |
| нельзя прервать и продолжить | чекпойнт «глава 2, параграф 3» |

Реализация (два пути, оба нужны):

1. **python-docx** — быстро, кроссплатформенно, управляем стилями:
   ```python
   doc = Document("template.docx")          # шаблон вуза, если дали
   p = doc.add_paragraph(style="Text_First")
   p.add_run(текст)
   # сноска: python-docx не умеет нативно → вставка XML-фрагмента footnote
   ```
   Ограничение: **сноски** и автосодержание делаются вставкой OOXML — нужен свой хелпер
   (в vault: `python-openxml/python-docx`, `elapouya/python-docx-template`).
2. **COM-автоматизация Word** (`pywin32`/`winax`) — «по-настоящему»: `Selection.TypeText`,
   `Footnotes.Add`, `TablesOfContents.Add`, обновление полей, экспорт PDF. Требует установленного
   Word; на Windows это норма.

Правило выбора: есть Word → COM (максимальная нативность); нет → python-docx + OOXML-хелперы.

## 4. Поиск и работа с источниками

| Шаг | Инструменты (в vault) |
| --- | --- |
| Веб-поиск | `ddgs`/`duckduckgo-search`, браузерный MCP |
| Научные базы | Crossref (`habanero`), OpenAlex (`pyalex`), Semantic Scholar, arXiv, PubMed |
| Скачивание и извлечение текста | `trafilatura` (лучший для веба), `readability-lxml`, `pdfminer.six`, `docling` для PDF с таблицами |
| Библиография | `citeproc-py`, CSL-стили ГОСТ (`citation-style-language/styles`), `bibtexparser` |
| Карточка источника | `{id, тип, авторы, название, год, издательство/журнал, DOI/URL, дата доступа, страницы, конспект 3–5 тезисов, где использован}` |
| Проверка существования | DOI-резолв, доступность URL, год издания, «не ИИ-статья» (эвристики) |

Отдельно: **сохранение** — папка проекта `Курсовая_<тема>/sources/` с PDF и `bib.json`,
плюс копия в память ZShelper (векторный индекс) для «а что там было в источнике 12?».

## 5. Против «ИИ-паттернов» (то, что просил пользователь)

Что считаем паттернами (проверяемо):

1. Вводные-пустышки: «Важно отметить, что…», «В современном мире…», «Следует подчеркнуть…».
2. Симметрия ради симметрии: три пункта всегда и везде, одинаковые абзацы по 4 предложения.
3. Отсутствие конкретики: нет чисел, дат, имён, ссылок — «многие исследователи считают».
4. Списки вместо рассуждения там, где нужен связный текст.
5. Лексические маркеры: «данный», «осуществляется», «является» в каждом предложении.
6. Выводы, повторяющие введение слово в слово.
7. Англицизмы и кальки в научном стиле.

Как исправляем:
- **Линтеры**: `vale` с собственным набором правил (RU + EN), `textlint`, `retext`, `write-good`.
- **Правила стиля** в промпте: «не начинай абзац с …, избегай …, конкретика обязательна».
- **Пасс переписывания**: по абзацу — «сохрани смысл, факты и ссылки, измени синтаксис, убери
  шаблоны, добавь конкретику из источника N». Сравнение «до/после» по метрикам:
  длина предложений (stdev), доля пассивных конструкций, TTR (лексическое разнообразие),
  число клише на 1000 слов.
- **Честность**: мы **не обещаем** обход детекторов ИИ. Детекторы ненадёжны и меняются;
  обещаем качественный, конкретный, цитируемый текст без шаблонных конструкций.

## 6. Юридическая грамотность (и её границы)

- Термины сверяем с первоисточником (НПА): «потребитель», «работник», «персональные данные» —
  определения из закона, а не «как кажется».
- Каждая ссылка на закон — с редакцией и датой: «ГК РФ, ст. 395 (ред. от …)».
- Проверка на подмену понятий и на противоречия внутри текста (агент-критик).
- **Дисклеймер в отчёте**: «это учебный текст, не юридическая консультация» — всегда.

## 7. Режим «работай, пока не скажу стоп»

Технически это `job` с бюджетом и циклом:

```yaml
job:
  kind: academic.paper
  autonomy: until_stop        # ключевое слово: не останавливаться на чекпойнтах
  budgets: { maxHours: 12, maxTokens: 4_000_000, maxDiskMb: 2048, maxActions: 5000 }
  checkpoints: every_chapter  # сохранять состояние, но НЕ спрашивать разрешения
  notifications: every_action # Telegram по каждому шагу (см. 10-safety §6)
  stop_words: ["стоп", "хватит", "остановись", "stop"]
  heartbeat: 20min
  on_error: { retry: 2, then: "replan", then: "notify-and-wait" }
```

Обязательные предохранители, иначе «бесконечная работа» превращается в бесконечный счёт за
электричество: лимит времени, лимит токенов, «три ошибки подряд → пауза и вопрос»,
«диск кончился → пауза», «пользователь вернулся за компьютер → отчёт о прогрессе».

## 9. Этика и ответственность (проговариваем в UI)

- ZShelper — **инструмент подготовки черновика** и организации источников, а не способ обмануть
  вуз. Ответственность за сдачу — на пользователе.
- По умолчанию: все ссылки реальные и проверяемые, цитаты — с кавычками и указанием страницы.
- В настройках есть «строгий академический режим»: запрещает вставку текста без источника
  (каждый абзац обязан иметь ссылку или быть явно «авторским рассуждением»).

## 11. Открытые вопросы

- ГОСТ 7.32 и правила оформления меняются, а вузы живут по своим методичкам → **источник истины
  всегда методичка**; нужен парсер методичек (PDF → checklist) и ручное подтверждение правил.
- Сноски в python-docx: писать свой OOXML-хелпер или требовать Word? Гипотеза: хелпер + fallback
  «концевые примечания».
- Антиплагиат: локальная оценка «похожести» по собственному корпусу источников — можно
  (шинглы + MinHash), но она **не равна** вузовской системе. Проговариваем в отчёте.
- Сколько источников реально доступно бесплатно (открытый доступ) — оценка: 40–60 % по
  экономике/праву/IT; остальное — только реферативно, без полного текста.
