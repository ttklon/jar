# 05 — Голосовой контур: слышать, понимать, отвечать, не мешать

Требования: R-01…R-04. Цель — «поговорил и сделал» с ощущением живого собеседника:
первое слово ответа ≤ 1.2 с, перебивание работает, ложных срабатываний почти нет.

## 1. Труба обработки

```
┌──── WASAPI capture 16 kHz mono f32, ring buffer 100 мс ────┐
│                                                            │
▼                                                            │
[1] AEC / noise suppression (опционально)                    │
▼                                                            │
[2] VAD (Silero, кадр 32 мс) ──нет речи──> отбрасываем       │
▼ есть речь                                                  │
[3] Wake-word gate (если режим wake)  ──нет фразы──> стоп    │
▼                                                            │
[4] Стриминговый ASR: partial каждые ~200–300 мс             │
▼                                                            │
[5] End-of-utterance: VAD-тишина 250–400 мс + пунктуация     │
▼                                                            │
[6] Финальный ASR (turbo) + нормализация + язык              │
▼                                                            │
[7] NLU: интент/слоты (tiny LLM) → план → инструменты        │
▼                                                            │
[8] Ответ: стриминг текста в UI + TTS по предложениям        │
▼                                                            │
[9] Barge-in: пользователь заговорил → duck/mute TTS + стоп  │
```

## 2. Захват аудио

- API: **WASAPI shared mode**, 16 кГц, моно, float32. Через нативный модуль
  (`naudiodon`-класс) либо собственный Rust-хелпер (`cpal`/`wasapi`) — второй надёжнее,
  но дольше.
- Буфер 20–40 мс, суммарная задержка тракта ≤ 100 мс (замеряется профилировщиком).
- Устройство выбирается в настройках, с горячей заменой (headset подключили — переехали).
- **Важно**: не запускать захват в main-процессе Electron — GC и логи дают дропы.

## 3. VAD и endpointing

- **Silero VAD v5** (ONNX, ~2 МБ, MIT) — дефолт. Порог 0.5, `minSpeechMs=200`, `minSilenceMs=300`.
- Адаптивный endpointing: если пользователь говорит медленно/паузами — увеличиваем тишину до
  600 мс; если быстро — 250 мс. Признак: средняя длина паузы в текущей сессии.
- «Не перебивай себя»: пока TTS говорит, VAD-порог выше (0.65), чтобы не реагировать на свой звук.
- Защита от «вечного слушания»: максимальная длина утterance 30 с → принудительная отсечка и
  запрос «продолжить?».

## 4. Wake word (R-02)

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| **sherpa-onnx KWS** (офлайн, своя фраза) | без ключей и лимитов | качество ниже Porcupine |
| **openWakeWord** (ONNX) | обучение своей фразе за минуты | требует синтетики для русского |
| **Porcupine** | лучшее качество | ключ, лимиты, не «полностью бесплатно» |
| Только PTT (Ctrl+Alt+Space) | 0 % ложных | не «руки свободны» |

Решение: **PTT по умолчанию**, wake-word — опция. Русская фраза «эй, хелпер»/«хелпер»
обучается на синтезе (Piper/Kokoro, 2–3 тыс. фраз) + аугментации (шум, реверберация, громкость,
микрофонные АЧХ). Антиложный фильтр: два срабатывания в течение 1.5 с **или** наличие
VAD-сегмента с речью ≥ 300 мс.

## 5. ASR-стратегия (двухпроходная)

| Проход | Модель | Зачем | Латентность |
| --- | --- | --- | --- |
| Быстрый partial | whisper.cpp `base`/`small` или sherpa-onnx streaming | показать текст, дать ощущение отзывчивости | 150–350 мс |
| Финальный | whisper `large-v3-turbo` Q5 / Parakeet / Qwen3-ASR | точность, пунктуация, команды | 300–800 мс (фраза 3–6 с) |

Приёмы, которые реально поднимают качество на русском:
1. **Промпт-словарь**: список терминов и имён (`CapCut`, `Telegram`, `коммит`, `пуш`,
   `рабочий стол`, имена папок). Whisper любит «подсказки».
2. **Нормализация чисел и команд** отдельным шагом («на двадцать процентов» → 20 %).
3. **Языковая автоопределённость** с приоритетом ru; при смешанной речи — `transcribe` с
   `language=ru` и постобработкой англицизмов.
4. **Отсечение галлюцинаций**: если VAD сказал «нет речи», текст выбрасывается; если
   `no_speech_prob > 0.6` и длина < 3 слов — выбрасываем; чёрный список типовых
   галлюцинаций («Спасибо за просмотр», «Продолжение следует»).

## 6. TTS и перебивание

- Синтез **по предложениям** (не по всему ответу) → первый звук через 300–500 мс.
- Очередь воспроизведения с приоритетом: срочные алерты > ответ > фоновые уведомления.
- **Ducking**: при старте речи пользователя громкость TTS → 20 % за 80 мс, затем стоп.
- **Barge-in**: во время речи работает VAD, но ASR включается только если VAD-сегмент
  длиннее 400 мс (иначе кашель/«э-э» убивает ответ). Стоп-слова («стоп», «хватит»,
  «подожди») распознаются отдельной крошечной моделью/регекспом на partial-тексте.
- Голос: дефолт — женский/нейтральный русский; скорость 1.0 (0.8–1.3 в настройках);
  «читать код» — с проговором символов; длинные блоки кода вслух не читаем (только
  «вставил в файл, показать?»).

## 7. Полудуплекс vs полный дуплекс

| Режим | Как | Когда |
| --- | --- | --- |
| Полудуплекс (просто и надёжно) | пока говорим — микрофон в mute (кроме детектора стоп-слов на loopback-вычитании) | дефолт на T0/T1 |
| Полудуплекс + AEC | WebRTC APM (AEC3): вычитаем свой сигнал из микрофона | T2+ |
| Полный дуплекс | отдельная duplex-модель (Moshi/Speech-to-Speech) | эксперимент, T3 |

Полный дуплекс — это отдельная архитектура (речевая LLM), а не «добавить AEC». В v1 не берём,
но держим в бэклоге: `sources/whisper-and-asr/kyutai-labs__moshi/`.

## 8. Бюджет латентности (целевые значения)

| Этап | Цель | Максимум |
| --- | --- | --- |
| Конец речи → VAD-сегментация | 250 мс | 400 мс |
| → финальный текст | 500 мс | 1200 мс |
| → первый токен ответа LLM | 600 мс | 2000 мс |
| → первый звук TTS | 400 мс | 900 мс |
| **Итого «услышал → заговорил»** | **~1.2 с** | 3 с |

Если бюджет нарушен — UI показывает «думаю…» и (опционально) короткое «сейчас» от TTS, чтобы
не было тишины. Никогда не «молчим 5 секунд»: лучше честное «секунду, смотрю экран».

## 9. Приватность 24/7 (R-02, R-23)

- Индикатор записи: пульсирующая иконка в трее + плашка в оверлее + звуковой маркер (опция).
- **По умолчанию аудио не сохраняется**: держим кольцевой буфер 60 с в RAM (для «повтори, что
  я сказал»), на диск — только если включён «дневник» (явно, с предупреждением).
- Всё распознавание локальное; ни один кадр аудио не уходит в сеть без явного действия
  (например, «отправь голосовое в Telegram»).
- Кнопки: «пауза на 15 минут», «стоп до завтра», «только PTT».
- Глобальные хоткеи: `Ctrl+Alt+Space` (PTT), `Ctrl+Alt+Esc` (СТОП всего), `Ctrl+Alt+H` (скрыть).

## 10. Сценарии, которые ломают наивную реализацию

| Ситуация | Что делать |
| --- | --- |
| Пользователь в наушниках, музыка играет | AEC + приоритет VAD на голосовых частотах; «не слышу — нажми PTT» |
| Эхо от колонок | ducking + AEC; предупреждение в настройках |
| Двое говорят | диаризация (опция), вопрос «к кому обращаетесь?» |
| Шум (пылесос, улица) | RNNoise/deepfilter + повышение порога VAD |
| Пользователь говорит по-английски внутри русского | авто-язык на уровне утterance |
| Долгая команда с паузами | адаптивный endpointing + «продолжай, слушаю» |
| Микрофон отвалился | авто-переподключение, алерт, переключение на PTT-хоткей |
| ПК на батарее | wake-word остаётся, тяжёлые модели пауза |

## 11. Реализация: модули

```
workers/audio/
├── capture.ts        // WASAPI → ring buffer
├── vad.ts            // Silero ONNX, сегментация
├── wake.ts           // KWS (sherpa-onnx) / openWakeWord
├── asr.ts            // whisper.cpp / sherpa-onnx, 2 прохода
├── tts.ts            // очередь синтеза + воспроизведение
├── aec.ts            // WebRTC APM (опция, нативный модуль)
└── state.ts          // машина состояний: idle|wake|listening|thinking|speaking|paused
```

Машина состояний (важно для предсказуемости):

```
idle ──PTT/wake──> listening ──endpoint──> thinking ──> speaking ──done──> idle
  ▲                    │                      │             │
  └────── cancel ──────┴────── cancel ────────┴── barge-in ─┘
```

Правило: переходы только через `state.ts`, каждое изменение — событие в UI и в аудит.
Иначе получаем классический баг «микрофон остался включённым».

## 13. Открытые вопросы

- Порог и обучение wake-word на русском: сколько синтетики достаточно для < 1 ложного
  срабатывания в сутки? Нужен собственный замер на 24-часовой записи.
- Тянет ли `sherpa-onnx` одновременно ASR-stream + TTS на T1 (iGPU) без конфликтов — замерить.
- AEC: нативный WebRTC APM (сложная сборка) vs простое «mute во время речи» (дешёво, но
  не даёт перебивать). Гипотеза: v1 — mute + детектор стоп-слов на loopback.
