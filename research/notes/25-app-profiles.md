# 25 — Профили приложений: слой «как именно» и почему без него «умеет всё» — ложь

Реестр (заметка 24) говорит **что** приложение умеет. Но «смонтировать видео» и «нарезать
клип в CapCut» — разные вещи: во втором нужно знать, где кнопка, чем проверить, что клип
реально разрезан, и что делать, если интерфейс обновился.

Этот слой — [`data/profiles/*.json`](../data/profiles) + валидатор
[`tools/profiles.py`](../tools/profiles.py) + отчёт [`docs/PROFILES.md`](../docs/PROFILES.md).

Текущий срез: **4 профиля / 32 операции / 0 нарушений**.

---

## 1. Три уровня описания (и запрет на смешивание)

```
РЕЕСТР      data/actions.psv      что бывает в мире            (562 действия)
ПРОФИЛЬ     data/profiles/*.json  как это сделать в программе  (якоря, шаги, проверки)
ИНСТРУМЕНТ  код                    чем именно нажимаем         (UIA, SendInput, ffmpeg)
```

Правило: **инструмент не знает про «смысл»**, профиль не знает про «железо», реестр не
знает про «кнопки». Если смешать — получается либо хрупкий скрипт, либо бесполезная
таблица без реализации.

## 2. Иерархия якорей: от надёжного к последнему средству

| Приоритет | Тип якоря | Почему | Когда ломается |
| --- | --- | --- | --- |
| 1 | **API/CLI** | нет интерфейса — нет хрупкости | если у приложения нет API |
| 2 | **UIA** (`AutomationId`, `Name`, `ControlType`) | не зависит от темы, DPI, языка вёрстки | Electron/Qt/игры с кастомным рендером |
| 3 | **Горячая клавиша / меню** | документировано, стабильно между версиями | если пользователь переназначил |
| 4 | **OCR-текст** | работает на канвасе и в вебе | масштаб, язык, шрифты |
| 5 | **Картинка (template match)** | последний шанс | любая смена темы/разрешения |

Профиль обязан объявить `fallback` для каждого якоря — «если UIA не нашёлся, пробуем
меню, потом OCR». Это не паранойя: обучение на одном разрешении и запуск на другом —
классическая причина «агент нажимает в пустоту».

## 3. Правило проверки: «нажал» ≠ «получилось»

Каждая операция обязана иметь `verify`. Валидатор **падает**, если проверки нет.

| Тип операции | Чем проверяем |
| --- | --- |
| Изменение в приложении | появился объект на таймлайне / изменилось число строк / виден текст (OCR) |
| Сохранение файла | файл существует, размер стабилен 2 с, `ffprobe`/`pypdf` дают ожидаемое |
| Отправка наружу | экран успеха + запись в журнал + Telegram |
| Настройка системы | повторное чтение параметра даёт новое значение |
| «Ничего не произошло» | тоже результат: явная проверка отсутствия ошибки |

Три подряд неудачных верификации = **остановка операции и алерт**, а не «попробуем ещё раз
пятьдесят раз». Иначе агент за минуту сделает 50 одинаковых поломок.

## 4. Дрейф интерфейса: как не врать пользователю

Сценарий неизбежен: приложение обновилось, якорь исчез. Поведение ZShelper:

1. **Не нажимать наугад.** Отсутствие якоря — это ошибка, а не повод «кликнуть рядом».
2. **Откат** к последнему чекпойнту (Ctrl+Z, закрыть без сохранения, восстановить бэкап).
3. **Сообщение**: «CapCut обновился, кнопка экспорта не найдена. Профиль надо перепроверить»
   — с кнопкой «показать, как я это делаю» (запись демонстрации).
4. **Обновление профиля** через запись действий человека → новые якоря → `verified_at`.
5. **Eval-кейс** «интерфейс изменился» прогоняется в CI на синтетическом профиле.

Поле `verified_at` — обещание: если профилю больше N месяцев и приложение обновилось,
он помечается «непроверенный» и операции требуют подтверждения.

## 5. Запись профиля по демонстрации (self-healing)

Человек показывает 1 раз — ZShelper записывает:

- события UIA (какие элементы получали фокус/клик), а не координаты;
- введённый текст **без значений** (только «здесь вводится путь/число»);
- скриншоты до/после для верификаторов;
- итог: операция + якоря + проверки.

Ограничения: запись не сохраняет пароли, не пишет клавиши в поля с `IsPassword=true`, не
записывает буфер обмена целиком. Демонстрация — источник *якорей*, не источник *секретов*.

## 6. Производительность на слабом ПК

| Приём | Выигрыш |
| --- | --- |
| UIA вместо OCR | нет модели, нет задержки на инференс |
| OCR только по области интереса | 5–20× меньше пикселей |
| Кэш найденных якорей по `(exe, version, dpi)` | повторные операции в 3–5 раз быстрее |
| Никаких постоянных скриншотов экрана | не жрём CPU/GPU в фоне |
| Шаблоны картинок в grayscale и уменьшенные | меньше памяти, быстрее match |

Бюджет: одна операция в GUI — **менее 2 с** на среднем ноутбуке; иначе выгоднее CLI-путь
(и профиль должен его предлагать как `fallback`).

## 7. Что уже описано (4 профиля)

| Профиль | Операции | Чем интересен |
| --- | --- | --- |
| CapCut | 9 | Electron без нормального UIA → горячие клавиши + OCR, экспорт проверяется `ffprobe` |
| Excel | 8 | UIA + Name Box, проверка формул на `#NAME?`, экспорт в PDF с подсчётом страниц |
| Проводник | 7 | пакетное переименование с проверкой коллизий, очистка корзины — destructive |
| Chromium (Chrome/Edge/Yandex) | 8 | persistent-профиль вместо паролей, парсинг DOM вместо кликов, robots.txt |

Следующие на очередь: Word, Photoshop, Premiere, Telegram Desktop, VS Code, 1С, Figma,
OBS, Steam, банковские клиенты (только «показать», без автоматизации операций).

## 8. Чего в профилях принципиально нет

- **Секретов** — только ссылки на `secrets.enc` / persistent-профиль браузера.
- **Абсолютных координат** там, где есть UIA.
- **Обхода защит**: капчи, анти-чита, DRM, лицензионных проверок. Если единственный путь —
  обход, операция помечается `never` в реестре.
- **Пиксель-в-пиксель скриптов** для операций, у которых есть API.

## 9. Как это усиливает главное требование

«Умеет всё» проверяемо складывается из трёх чисел:

- **613** строк реестра — широта (что вообще бывает);
- **32** операции в профилях — глубина (что уже доведено до кнопок и проверок);
- **0** нарушений инвариантов — честность (нет операций без проверки и без строки реестра).

Широта без глубины — это презентация. Глубина без широты — это один скрипт. Продукт —
когда растут оба числа, а нарушения остаются нулём.
