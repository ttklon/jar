# 03 — Каталог моделей по ролям

> **Главная идея:** не «одна модель на всё», а **ансамбль специалистов**, где каждая роль
> закрывается минимально достаточной моделью. Это и есть «куча маленьких моделей под задачи».
>
> **Дата срезки: ноябрь 2026.** Любая строка старше ~6 месяцев перепроверяется
> (`tools/collect_sources.py discover`). Где я не уверен в точных цифрах — стоит `⚠️ проверить`.

## 0. Роли и почему их нельзя склеивать

| Роль | Почему отдельная модель |
| --- | --- |
| Wake word | всегда слушает, 1–5 МБ, не может быть LLM |
| VAD | определяет «конец фразы», критичен для латентности |
| ASR | другой тип сети (audio→text), не конкурирует с LLM за VRAM при стриминге |
| Диаризация | «кто говорит», нужна для 24/7-заметок и встреч |
| TTS | audio-out, стриминг по предложениям |
| Embedding | индекс памяти/файлов, работает постоянно |
| Reranker | точность поиска, дешёвый |
| OCR | текст с экрана без VLM (быстро и без галлюцинаций) |
| VLM / grounding | «где кнопка», понимание интерфейса |
| Tiny LLM | классификатор намерений, роутер, извлечение слотов (0.6–1.7B) |
| Workhorse LLM | диалог, планы, объяснения (3–8B) |
| Coder LLM | код, диффы, тесты |
| Critic / safety | проверка плана на опасность, «адвокат дьявола» |

Склеивать их в одну модель = платить латентностью и качеством везде. Но и плодить 12 моделей
нельзя: **на T0 одновременно живут 2–3, на T3 — 4–6**, остальные грузятся по требованию.

Практика:
- Русский: `large-v3-turbo` Q5 + VAD Silero + промпт-подсказка со словарём (`пуш`, `коммит`,
  имена приложений). Это даёт больше, чем смена модели.
- Стриминг: два прохода — быстрый `small`/`base` для partial-текста, `turbo` для финального
  уточнения. Пользователь видит текст мгновенно, команда исполняется по финалу.
- Холллюцинации Whisper на тишине — отсекать VAD-ом и «нет речи → нет текста».

обязательный антиложный фильтр: 2 срабатывания подряд или наличие VAD-сегмента.

## 4. Понимание экрана: OCR и VLM

| Роль | Кандидат | Размер | Лицензия | Заметки |
| --- | --- | --- | --- | --- |
| OCR быстрый | **RapidOCR (PP-OCRv4/v5, ONNX)** | 10–60 МБ | Apache-2.0 | Русский+английский, CPU, ~50–150 мс на экран |
| OCR точный | **PaddleOCR full** | 100–300 МБ | Apache-2.0 | Таблицы, сложные раскладки |
| OCR простой | Tesseract 5 (rus+eng) | 30 МБ | Apache-2.0 | Fallback, хуже на скриншотах UI |
| Документы | **Surya / Docling / Marker** | 0.5–2 ГБ | GPL/Apache ⚠️ | PDF→markdown с таблицами (лицензии проверить!) |
| OCR-LLM | **DeepSeek-OCR** | ~3B | MIT ⚠️ | Мощно, но тяжело для слабых ПК |
| Grounding | **OmniParser v2** | детектор+captioner, ~1–2 ГБ | MIT | Скриншот → список интерактивных элементов с координатами |
| VLM-агент | **UI-TARS-2B / 1.5-7B / TARS-2** | 2–7B | Apache-2.0 | Обучен на UI, знает Windows-паттерны, отдаёт координаты |
| VLM общий | **Qwen2.5-VL-3B / Qwen3-VL** | 3–7B | Apache-2.0 | «Что на экране», «почему ошибка» |
| VLM лёгкий | **Moondream 2/3, SmolVLM2** | 0.25–2B | Apache-2.0 | T1: грубое описание, не для точных кликов |

**Правило точности:** координаты кликов никогда не берём «на глаз» от VLM — только через
UIA-дерево, OmniParser или CV-детекцию элемента, с проверкой «после клика состояние изменилось».
VLM здесь — советчик, не исполнитель.

## 7. Как выбрать квант

1. Считаем бюджет по формулам из `02-hardware-profiler.md`.
2. Если влезает `Q5_K_M` с нужным контекстом — берём его (заметно лучше Q4 на мелких моделях).
3. Если нет — `Q4_K_M` (стандарт де-факто).
4. `Q3_K_M`/`IQ3` — только T0/T1 и только для «мозга», не для кода.
5. `Q8_0` — для embedding/OCR/rerank (там качество важнее, модели мелкие).
6. KV-кэш квантовать (`--cache-type-k q8_0`) можно — экономит 30–50 % VRAM почти без потерь.

## 8. Температура и сэмплирование (частые грабли)

Из карточки Qwen3: thinking-режим — `temp 0.6`, `top_p 0.95`, `top_k 20`, **не** greedy;
non-thinking — `temp 0.7`, `top_p 0.8`. При зацикливании — `presence_penalty 1.5`.
Для tool-calling и JSON — `temp ≤ 0.3` + грамматика/схема (constrained decoding), иначе
мелкие модели «изобретают» аргументы.

## 9. Tool-calling на мелких моделях: горькая правда

Эмпирика (подтверждается обзорами и бенчмарками вроде BFCL):
- 0.6–1.7B **не** держат 20 инструментов в контексте — путают аргументы и выдумывают поля.
- Работает связка: **retrieval 5–8 инструментов + один вызов за шаг + JSON-схема +
  валидация + «повтори с ошибкой валидатора»**.
- Планирование лучше делать отдельной моделью (или кодом), а не «пусть LLM сама решает».
- Итог: архитектура «роутер → один инструмент → проверка → следующий шаг» побеждает
  «дай модели 40 инструментов и надейся».

## 10. Модельный манифест (`model-lock.json`)

```jsonc
{
  "schema": 1,
  "profileTier": "T2",
  "models": [
    { "role": "llm.workhorse", "id": "Qwen3-8B-GGUF", "file": "qwen3-8b-q4_k_m.gguf",
      "sha256": "…", "sizeBytes": 5030000000, "source": "hf:Qwen/Qwen3-8B-GGUF",
      "license": "Apache-2.0", "ctx": 16384, "runtime": "llama-server",
      "args": { "nGpuLayers": "auto", "flashAttn": true, "cacheTypeK": "q8_0" } },
    { "role": "asr.ru", "id": "whisper-large-v3-turbo", "file": "ggml-large-v3-turbo-q5_0.bin",
      "sha256": "…", "sizeBytes": 574000000, "source": "hf:ggerganov/whisper.cpp",
      "license": "MIT", "runtime": "whisper.cpp" }
  ]
}
```

Свойства манифеста:
- **Без сети**: файл + sha256, скачивание докачиваемое, с зеркалами (HF, ModelScope, GitHub
  Releases) — у пользователя может быть медленный/недоступный HF.
- **Проверка целостности** обязательна: подмена весов = удалённый код.
- **Откат** на предыдущий манифест, если новая модель хуже по тестам.
- **Экономия диска**: TTL-кэш, «держать только текущий tier + один запасной».

## 11. Что тестировать самим (не верить лидербордам)

Малый набор из 40–60 задач на русском:
1. 10 команд «создай/переименуй/найди файл»;
2. 8 команд с неоднозначностью («убери это» после выделения);
3. 6 многошаговых («найди видео, скачай, перескажи»);
4. 10 tool-calling кейсов (аргументы, отказы, опасные действия);
5. 8 кодинг-задач (функция + тест);
6. 6 вопросов «на понимание контекста экрана».

Метрики: exact-match аргументов, успех шага, число лишних шагов, время до первого слова,
доля галлюцинаций. См. `15-evals.md`.
