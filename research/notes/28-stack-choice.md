# 28 — На чём писать ZShelper: язык, оболочка, упаковка (решение с обоснованием)

Вопрос был прямой: «Electron я выбрал потому, что Python ужасен; есть ли что-то лучше?»
Отвечаю так же прямо: **Python для поставки — нет, Electron — можно, но не лучший вариант
именно под защиту и «вид настоящего приложения». Оптимально — Tauri 2 (Rust-ядро + web-UI),
а если нужен буквально нативный вид Windows — C# + WinUI 3.**

Ниже — цифры, компромиссы и что это меняет в плане проекта.

---

## 1. Короткий ответ (для тех, кто читает только первый абзац)

| Вариант | Размер | Защита кода | Нативный вид | Скорость разработки | Вердикт |
| --- | --- | --- | --- | --- | --- |
| Python (PyInstaller) | 40–120 МБ | ⚠️ **очень слабая** (`pyinstxtractor` + декомпилятор) | нет | низкая (упаковка, DLL, антивирусы) | **только для внутренних инструментов** |
| Electron 43+ | 85–250 МБ | ⚠️ слабая: `app.asar` распаковывается одной командой, JS читается | средний (CSS рисует что угодно) | высокая | допустимо, но нужно 6 слоёв защиты |
| **Tauri 2** | **3–15 МБ** | ✅ лучше: ядро — скомпилированный Rust, наружу отдан только UI | хороший (WebView2 + Mica/кастомный титул) | средне-высокая (нужен Rust) | **рекомендую** |
| C# + **WinUI 3** | 5–40 МБ | ⚠️ IL декомпилируется; лечится обфускацией/NativeAOT | ✅ **максимально нативный** (Fluent) | средняя (XAML) | если «как из Microsoft Store» буквально |
| C++/Qt | 20–60 МБ | ✅ хорошая | ⚠️ Qt-вид ≠ Fluent без работы | низкая | не для одного разработчика |
| Flutter | 30–60 МБ | ⚠️ Dart-снапшот, но есть `blutter` | ⚠️ Material, не Fluent | средне-высокая (Dart) | не под Windows-first |

Ключевой факт, который чаще всего упускают: **Electron не защищает код вообще**.
`app.asar` — это архив, а не шифрование; официальная позиция Electron это прямо признаёт [1].
То есть «на Electron нельзя разобрать» — иллюзия; можно, за 30 секунд.

## 2. Почему Python не подходит для поставки (подтверждение твоего опыта)

1. **Декомпиляция.** PyInstaller-сборка разбирается `pyinstxtractor`, байткод восстанавливается
   до читаемого Python. Даже без исходников видно логику лицензии.
2. **Упаковка.** DLL, VC++ redistributable, антивирусы, ложные срабатывания, «missing
   `python3xx.dll`» на чужих машинах — это не «капризы», а реальные часы поддержки.
3. **Вид.** Tkinter/PyQt без вложений выглядят «инженерной утилитой». Красивый UI на Python
   возможен (PySide6 + QML), но это уже не «просто Python», а фактически Qt-проект.
4. **Производительность на слабом ПК.** GIL + упаковка + десятки зависимостей = долгий старт.

Итог: Python остаётся **отличным языком для внутренних скриптов, обучения моделей и тулинга**
(и у нас он уже используется для генераторов реестра/отчётов), но не для продукта по подписке.

## 3. Electron: где он выигрывает и где именно ломается подписка

**Выигрывает:**

- одинаковый рендеринг Chromium на всех ОС — «что нарисовал, то и у клиента»;
- огромная экосистема: `node-pty`, `sharp`, `nut.js`, MCP TypeScript SDK — почти всё, что нужно
  ZShelper, уже есть готовыми npm-пакетами;
- зрелый автоапдейт (`electron-updater`), подпись, MSIX-обёртки;
- твой личный опыт: ты его знаешь, а значит скорость первой версии максимальная.

**Ломается ровно там, где начинается продажа:**

| Проблема | Что это значит |
| --- | --- |
| `app.asar` не защищает | любой `npx asar extract` даёт исходники; «AGI-агенты» разберут за минуты |
| 120–250 МБ на установку | дорогой трафик, апдейты по 100+ МБ, плохая конверсия скачивания |
| 100–300 МБ RAM в простое | противоречит требованию «работает на слабом ПК» |
| Полный Chromium + Node | каждая CVE Chromium — твоя CVE, пока не обновишься |

Защитить Electron **можно** (см. §6), но это постоянная работа: фьюзы, integrity, байткод,
обфускация, нативный модуль для лицензии. Проще сразу выбрать оболочку, где ядро уже нативное.

## 4. Рекомендация: Tauri 2 + Rust-ядро + React/Svelte UI

### Почему именно это

1. **Размер и память.** Реальные замеры 2026: Tauri 1–15 МБ против Electron 85–250 МБ;
   idle-память 30–80 МБ против 100–300 МБ; холодный старт ~380 мс против ~1400 мс [2][3].
   Честная поправка: на Windows Tauri использует WebView2 (это тот же Chromium от Microsoft),
   поэтому разница в памяти при открытом окне может быть всего ~5 % [4] — но размер,
   установка и апдейты выигрывают всё равно в разы, и это влияет на продажи.
2. **Защита.** Всё, что дорого (лицензия, проверка целостности, работа с файлами, автоматизация),
   живёт в **Rust-ядре** — это машинный код, а не читаемый JS. Наружу отдаётся только UI.
   Это принципиально: в Electron *вся* логика — JS.
3. **Модель прав.** Capabilities: окно не получает доступ к системе, пока ты явно не разрешишь
   команду. Для приложения, которое «умеет всё», это обязательная страховка [5].
4. **Windows-first дружелюбен.** WebView2 предустановлен на Windows 11 и на Windows 10 с
   обновлениями (Edge); Win10 1809+ — рабочая цель.
5. **Автообновления с подписью.** `tauri-plugin-updater` требует подписанные манифесты —
   из коробки то, что мы уже спроектировали в `22-updates.md`.

### Конкретный стек (можно брать как есть)

| Слой | Выбор |
| --- | --- |
| UI | React 19 + TypeScript + Vite; компоненты Fluent UI React v9 (вид Windows) + Tailwind для раскладки |
| Оболочка | Tauri 2, окно с Mica/Acrylic, кастомный титул-бар, трей |
| Ядро | Rust: `windows` (Win32/UIA/COM), `enigo` (ввод), `xcap` (экран), `ort` (ONNX Runtime), `whisper-rs`, `image`, `tokio` |
| Лицензия | Rust-модуль: `ed25519-dalek`, отпечаток машины + ключ в TPM через NCrypt |
| ИИ-движки | отдельные процессы-сайдкары: `llama.cpp`, `whisper.cpp`, PaddleOCR, Piper/Kokoro — общаются по localhost HTTP |
| Апдейты | `tauri-plugin-updater` (Ed25519-манифест, дельта-обновления) |
| Упаковка | MSIX (+ NSIS как альтернатива), подпись Azure Artifact Signing |
| Сервер лицензий | Rust Axum **или** Node Fastify + Postgres + Caddy (см. `29-licensing-and-antipiracy.md`) |

### Что мигрировать из Electron-плана

Реально переносится 1:1: **весь UI** (React-компоненты), дизайн-система, логика экранов,
форматы настроек. Меняется «низ»:

| Было (Node/Electron) | Стало (Rust/Tauri) |
| --- | --- |
| `node-pty` | `portable-pty` |
| `sharp` | `image` + `libvips` (через `vips-sys` при необходимости) |
| `nut.js` / `robotjs` | `enigo` + UIA-обёртки |
| `electron-updater` | `tauri-plugin-updater` |
| JS-оркестратор/планировщик | Rust (Tokio) — быстрее и не виден в бинарнике |
| MCP-серверы (Node) | остаются сайдкарами — это нормально, они отдельные процессы |

**Риск миграции:** 2–4 недели на оболочку + 1–2 недели на самые «нативные» фичи
(UIA-автоматизация, захват экрана, OCR-пайплайн). Это дешевле, чем потом переделывать
защиту и упаковку под подписку.

## 5. Альтернатива, если хочется «прям как из Microsoft Store»: C# + WinUI 3

- WinUI 3 входит в Windows App SDK (1.8 — стабильная, 2.0 preview под .NET 10),
  поддерживает **Windows 10 1809+** и Windows 11, упаковывается в MSIX или без упаковки [6][7].
- Вид — родной Fluent: Mica, Acrylic, системные контролы, корректный DPI, доступность из коробки.
- Автоматизация Windows из C# — самая сильная сторона: `UIAutomationClient`, `FlaUI`, COM к Office.
- Защита: C#-IL декомпилируется (ILSpy/dnSpy) → нужна обфускация или **NativeAOT**;
  тогда получается машинный код, сопоставимый по стойкости с Rust, но с потерей части рефлексии.
- Минус: UI на XAML медленнее в разработке, чем HTML/CSS, и «красиво» сделать дороже.

**Когда брать WinUI 3:** если приоритет — нативность и Store-канал, а UI готов писать на XAML.
**Когда брать Tauri:** если приоритет — скорость, красивый кастомный UI, маленький установщик,
и ты готов держать ядро на Rust.

## 6. Если всё-таки остаёмся на Electron (минимум защиты)

Обязательный набор (по официальной документации Electron и практикам 2026) [1][8]:

1. **Fuses:** `EnableEmbeddedAsarIntegrityValidation`, `OnlyLoadAppFromAsar`,
   `RunAsNode: false`, `EnableNodeCliInspectArguments: false`.
2. **ASAR integrity** — при подмене архива приложение завершается.
3. **V8 bytecode** (`bytenode`) для критичных модулей — не читаемый JS.
4. **Обфускация** (`javascript-obfuscator`, control-flow flattening) — только для лицензионного кода.
5. **Нативный addon на Rust** (napi-rs) для проверки лицензии и целостности — чтобы ключевая
   проверка была не в JS.
6. **Подпись + MSIX**, чтобы Windows не показывала «неизвестный издатель».

Это работает, но даёт примерно «средний» уровень: код всё равно восстановим, вопрос — за сколько часов.

## 7. Что делает приложение «не кустарным», кроме языка

Пользователь судит не по фреймворку, а по шести вещам:

1. **Установщик и подпись.** MSIX/NSIS + Authenticode; без подписи — «Windows защитила ваш ПК»
   и половина пользователей уходит.
2. **Иконка, шрифты, отступы, тёмная тема, DPI** — визуальная дисциплина важнее технологии.
3. **Онбординг:** первый запуск за 60 секунд (выбор профиля железа → 3 вопроса → готово).
4. **Автообновления без перезагрузки** и понятный changelog.
5. **Красивые ошибки:** «не смог, потому что X, вот что делать» вместо трейсбека.
6. **Скорость:** окно и первый ответ < 1 с на среднем ноутбуке.

## 8. Итоговое решение (и что меняется в плане)

**Решение:** ZShelper v1 — **Tauri 2 (Rust-ядро) + React/Fluent UI**, упаковка **MSIX + NSIS**,
подпись **Azure Artifact Signing**, апдейты — **подписанные Ed25519-манифесты**.
WinUI 3 держим как резервный путь, если UI на web-стеке упрётся в нативность.
Electron остаётся допустимым «быстрым прототипом», но не целевой платформой релиза.

Изменения в дорожной карте:

- M1: каркас — Tauri 2, а не Electron; capability-манифест пишем сразу.
- M2: добавляется **сервис лицензий на VPS** (см. `29-licensing-and-antipiracy.md`) и подпись сборок.
- M6 (сборка/CI): GitHub Actions собирает MSIX, подписывает, публикует релиз с манифестом.
- M8: миграция существующих профилей приложений не требуется — профили это данные.
