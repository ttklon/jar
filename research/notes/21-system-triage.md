# 21 — Разбор и оптимизация системы: «что грузит компьютер», службы, двойники

Три сценария пользователя:
1. «Открой диспетчер задач и скажи, что грузит систему: каждая служба — что это, откуда,
   важна ли, можно ли отключить/удалить».
2. «Оптимизируй систему, чтобы освободить ресурсы».
3. «Пройдись по всем папкам, найди двойников и удали».

Это самая «разрушительная» зона продукта. Отсюда правило: **сначала объяснение, потом
рекомендация, и только потом — действие с точкой восстановления.**

## 1. Откуда берём данные (без «диспетчера задач на глаз»)

| Слой | API/источник | Что даёт |
| --- | --- | --- |
| Процессы | `Get-Process`, `Win32_Process`, ETW | CPU, RAM, IO, путь, подпись, родитель, командная строка |
| Службы | `Win32_Service`, `sc queryex`, `tasklist /svc` | имя, отображаемое имя, тип запуска, состояние, путь, PID, зависимости |
| svchost-группы | `tasklist /svc /fo csv` | какой сервис в каком `svchost` |
| Автозапуск | `Autoruns`-категории: Run/RunOnce, StartupApproved, Task Scheduler, Services, WMI-подписки, shell-расширения, LSA, драйверы | всё, что стартует само |
| Планировщик | `Get-ScheduledTask`, `schtasks /query /xml` | триггеры, действия, автор |
| Диск | `Win32_PerfFormattedData`, `diskusage`, `fsutil` | объём, скорость, топ-пожиратели |
| Память | `Get-Counter`, `Win32_PerfRawData`, standby list | кто реально держит RAM |
| GPU | `nvidia-smi`, `dxdiag`, ETW | VRAM, загрузка, драйвер |
| Сеть | `Get-NetTCPConnection`, `netstat -b` (админ) | кто в сеть, куда |
| Надёжность | `Get-WinEvent` (System/Application, Critical/Error) | что падает и почему |
| Железо | `LibreHardwareMonitor`, SMART | температура, здоровье диска |
| Подписи | `Get-AuthenticodeSignature`, WinTrust | «кто издатель» и «доверенный ли» |

Всё это складывается в **снимок** (`performance-snapshot.json`) — с ним можно работать
офлайн, показывать диффы «до/после» и не зависеть от того, что открыто на экране.

## 2. База знаний «что это за служба» (ключевой актив)

Чтобы отвечать «насколько она важна, откуда, можно ли отключить», нужен локальный каталог:

```jsonc
{
  "id": "SysMain",
  "displayName": "SysMain (Superfetch)",
  "publisher": "Microsoft",
  "path": "C:\\Windows\\System32\\svchost.exe -k netsvcs",
  "whatItDoes": "Упреждающая загрузка часто используемых приложений в RAM.",
  "criticality": "medium",          // critical | high | medium | low | unknown
  "disableImpact": "На HDD — заметно медленнее первый запуск программ; на NVMe — почти незаметно.",
  "recommendation": "leave",        // leave | optional-off | off-on-hdd | never-touch
  "myth": true,                     // «отключение SysMain ускоряет Windows» — спорно
  "sources": ["Microsoft Learn: SysMain", "…"],
  "riskOfDisable": "low"
}
```

Наполнение: документация Microsoft, сайты вендоров, сообщество + собственные замеры.
Целевой объём v1: **200–300** самых частых служб/процессов/автозапусков (покрывает ~95 %
«что это такое?»). Обновляется как данные, не как код.

## 3. Формат ответа пользователю (голосом и в отчёте)

Топ-10 «пожирателей» + отдельно «подозрительное». Для каждой строки:

```
1. Antimalware Service Executable (MsMpEng.exe) — Defender
   CPU 12 %, RAM 380 МБ · Microsoft, подпись ✅
   Что делает: сканирует файлы в реальном времени.
   Можно ли отключить: нет (и не нужно). Можно исключить папки из проверки.
   Рекомендация: добавить в исключения папки моделей ZShelper и node_modules.
2. Steam (steam.exe) — автозапуск
   RAM 420 МБ · Valve, подпись ✅
   Рекомендация: убрать из автозапуска (игра сама запустит Steam). Освободит ~420 МБ.
   Откат: одна кнопка «вернуть в автозапуск».
```

Голосом — то же, но короче: «Самый прожорливый — Steam, 420 мегабайт в простое. Убрать из
автозапуска?». Длинные списки голосом не читаем — «подробности в отчёте, открыть?».

## 4. Классы рекомендаций и их безопасность

| Класс | Пример | Подтверждение | Откат |
| --- | --- | --- | --- |
| `read-only` | «покажи топ-10» | не нужно | — |
| `safe-off` | убрать из автозапуска Steam, Discord | 1 клик | вернуть в автозапуск |
| `caution` | отключить SysMain на HDD, уменьшить анимации | подтверждение + объяснение | скрипт отката |
| `risky` | отключить службы телеметрии/обновлений, изменить page file | **двойное** подтверждение + точка восстановления | снимок реестра + откат |
| `never` | Defender, Audio, Network, Cryptographic Services, RPC | запрещено, объясняем почему | — |

Правило «трёх нет»: не отключаем по умолчанию ничего, что влияет на безопасность, звук/сеть
и установку обновлений. Пользователь может настоять — но с явным предупреждением и точкой
восстановления, и мы **запоминаем**, что это его решение.

## 5. Что реально даёт эффект (и что миф)

По приоритету (для слабого ПК):

1. **Автозапуск** — 5–40 процессов, 0.3–1.5 ГБ RAM. Самый большой и безопасный выигрыш.
2. **Фоновые «жирные» приложения** (Steam, Discord, OneDrive-клиенты, RGB-утилиты) — RAM и CPU.
3. **Индексация и антивирусные исключения** — диск и CPU (исключить `models/`, `node_modules/`).
4. **Схема питания** и **визуальные эффекты** (на слабых GPU) — по желанию пользователя.
5. **Драйверы GPU/чипсета** — иногда дают больше, чем все твики вместе.
6. **Bloatware** (предустановленный софт) — удаление через winget/штатный установщик.
7. **Планировщик** — задачи обновлений/телеметрии в неудобное время.
8. **Page file / кэш** — трогать не нужно, кроме специфических случаев.

Мифы, которые **не** рекомендуем (и говорим об этом): «реестр-чистильщики», «RAM-booster»,
«отключить Superfetch везде», «удалить `WinSxS` руками», «отключить Defender», «поставить
максимальную производительность в BIOS».

## 6. Двойники: как искать (и почему это не «просто размер»)

```
Шаг 1: инвентаризация (без чтения содержимого): путь, размер, mtime, тип
Шаг 2: группировка по размеру (только кандидаты, ±0 байт)
Шаг 3: быстрый хэш первых/последних 64 КБ
Шаг 4: полный хэш (blake3) для прошедших
Шаг 5: для медиа — perceptual hash (pHash для изображений, кадровый хэш для видео,
        chromaprint для аудио), чтобы находить «почти одинаковые»
Шаг 6: для документов — извлечение текста + shingle/MinHash (Jaccard > 0.8)
Шаг 7: группы → «оставить лучший» (больше разрешение, новее, короче путь)
Шаг 8: карантин (перемещение в `ZShelper/quarantine/<date>/`) + отчёт CSV/JSON
```

По умолчанию **исключаем**: `C:\Windows`, `Program Files`, `$Recycle.Bin`, `System Volume
Information`, `.git/`, `node_modules/`, `AppData` (если не указано иное), символические ссылки
и junction'ы (иначе можно «удалить» не то).

Удаление — только через карантин + подтверждение списка. «Удалить всё» одной кнопкой — нельзя
(только «переместить в карантин всё отмеченное»). Очистка карантина — отложенно (7–30 дней)
или по кнопке.

## 7. Замеры «до/после» (чтобы не было самообмана)

- Idle: 5 минут без действий → средняя загрузка CPU, занятая RAM, количество процессов.
- Старт приложений: холодный запуск 3 программ (Explorer, браузер, Word).
- Диск: свободное место.
- Энергия: `powercfg /batteryreport` (ноутбук).
- Отчёт: таблица «было / стало / Δ», с честной пометкой «в пределах шума», если Δ < 5 %.

## 8. Безопасность и этика

- Перед любым `caution`/`risky`: **точка восстановления** (`Checkpoint-Computer`) + снимок
  ключей реестра/служб, которые меняем.
- Все изменения — в журнале с точной командой и параметром «как откатить».
- Никогда не отключаем: Defender, Windows Update (можно отложить), Audio, Network, RPC,
  Cryptographic Services, Plug and Play.
- Не устанавливаем «оптимизаторы» из интернета — только собственные проверенные действия.
- Если пользователь — не владелец машины (корпоративная), предупреждаем: политики домена
  могут запрещать; не обходим.

## 9. Голосовые сценарии (как это звучит)

> «Хелпер, что у меня грузит компьютер?» → снимок 3 с → «Три процесса: Defender 12 %, Steam 8 %,
> браузер 6 %. Больше всего памяти ест браузер — 2.1 ГБ. Показать подробно?»

> «Оптимизируй» → «Предлагаю 4 безопасных шага: убрать 6 программ из автозапуска, исключить
> две папки из проверки Defender, отложить обновления на ночь, отключить анимации.
> Освободит ~1.2 ГБ и снизит фон на 8 %. Делать по шагам или всё сразу?»

> «Найди двойников во всех папках» → «Нашёл 1 234 группы, 8.7 ГБ. Показываю топ по размеру.
> Предлагаю переместить в карантин 812 файлов, оставив по одному в группе. Проверить список?»

## 11. Открытые вопросы

- База знаний служб: 200 записей вручную — или полуавтомат (LLM + проверка человеком)? Гипотеза:
  LLM готовит черновик из документации, человек проверяет; хранится как данные с версией.
- Как быть с русскоязычными названиями служб и локализованной Windows — нужен маппинг
  `internalName → displayName[lang]`.
- Дедуп видео: кадровый хэш дорог (декодирование). Гипотеза: только по запросу и только для
  файлов < 500 МБ, с прогрессом.
- Стоит ли делать «откат всего» одной кнопкой (полный снимок изменений за сессию)? Да — это
  главный аргумент доверия: «одна кнопка — как было».
