# 23 — Всё настраивается: архитектура настроек

Требование пользователя: «вообще всё в приложении настраивается, максимально удобно».
Формализуем: **единая схема настроек = единственный источник истины** для UI, валидации,
документации и миграций.

## 1. Принцип: settings-as-schema

```ts
// shared/settings/schema.ts
export const SETTINGS = {
  "voice.outputMode": {
    type: "enum", values: ["voice", "text", "both", "auto"], default: "both",
    label: { ru: "Как отвечать", en: "Response mode" },
    help: "Голосом, текстом или и то и другое. «Авто» — голос для коротких ответов.",
    group: "voice", level: "basic", requiresRestart: false,
    impact: "Влияет только на способ вывода, не на действия.",
  },
  "voice.bargeIn": { type: "bool", default: true, group: "voice", level: "advanced", … },
  "models.tier": { type: "enum", values: ["auto", "T0", "T1", "T2", "T3"], default: "auto", … },
  "perf.ramLimitPct": { type: "int", min: 30, max: 90, default: 60, unit: "%", … },
  …
} as const;
```

Из этой схемы автоматически:
1. **UI** (react-jsonschema-form или свой рендер по `type`/`group`/`level`);
2. **валидация** в ядре (ajv/zod) — рендерер не может записать мусор;
3. **миграции** (`schemaVersion` + правила переименований);
4. **`--help` / документация** (генерируется);
5. **экспорт/импорт** настроек и **«объяснить эту настройку»** (LLM по `help`).

## 2. Уровни сложности (чтобы не пугать)

| Уровень | Что видно | Для кого |
| --- | --- | --- |
| **Basic** (5 экранов) | голос, модели, разрешения, уведомления, обновления | 95 % пользователей |
| **Advanced** | + производительность, память, инструменты, скиллы, хоткеи, тема | продвинутые |
| **Expert** | всё + JSON-редактор + импорт/экспорт + «опасные» тумблеры | автор/отладка |

Плюс **пресеты профилей**: «Слабый ПК» (T0/T1, минимум моделей, экономия), «Ноутбук»
(батарея, тишина), «Максимум» (T3, все модели, агрессивная параллельность), «Свой»
(сохранённые копии конфигурации с именами).

## 4. Правила UX настроек

1. **Поиск по настройкам** (по названию, описанию, синонимам: «микрофон» → «устройство ввода»).
2. У каждой настройки — **одна строка «что изменится»** и ссылка «объяснить подробнее» (LLM +
   документация).
3. Опасные настройки (отключить подтверждения, разрешить сеть всем, «автоустанавливать
   расширения») — за отдельным подтверждением и с датой/сроком действия.
4. **Кнопка «вернуть по умолчанию»** у каждого раздела и глобально.
5. **Диф перед применением** для импорта настроек: «что изменится» списком.
6. Ничего не применяется «молча»: изменения либо мгновенные (с тостом), либо помечены
   «требует перезапуска» с кнопкой.
7. Все изменения пишутся в аудит (кто/когда/что), чтобы «почему оно так себя ведёт» имело ответ.

## 5. Хранение и миграции

```
%APPDATA%/ZShelper/
├── settings.json          # {schemaVersion: 7, values: {...}}
├── settings.local.json    # машинно-специфичные (пути, устройства) — не экспортируется
├── secrets.enc            # DPAPI: токены, ключи (никогда в settings.json)
└── backups/settings.v6.json
```

- `schemaVersion` + миграции (функции `v6→v7`), применяются при старте, с бэкапом.
- Валидация при загрузке: неизвестные ключи сохраняем (forward-compat), невалидные — сбрасываем
  к дефолту и пишем в лог.
- Экспорт/импорт: JSON без секретов; импорт — с диффом и подтверждением.
- Отладка: переменные окружения `ZSH_*` перекрывают значения (для CI/тестов).

## 6. CLI и автоматизация (для «продвинутых»)

```powershell
ZShelper.exe --profile=t1 --voice=off --no-tray        # запуск с профилем
ZShelper.exe settings:get models.tier
ZShelper.exe settings:set perf.ramLimitPct=70
ZShelper.exe job:run "создай папку Демо на рабочем столе" --report
```

Один и тот же код: CLI — тонкая обёртка над IPC-методами ядра.

## 8. Открытые вопросы

- Генерировать UI из схемы полностью (rjsf) или писать компоненты, а схему использовать для
  валидации? Гипотеза: гибрид — rjsf для «продвинутых» разделов, кастомные экраны для основных.
- Сколько настроек «слишком много»? Порог: в Basic ≤ 25 параметров, в Advanced ≤ 150.
- Нужны ли «профили per-app» (например, для игр — всё выключить)? Да, как часть пресетов.
