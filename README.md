# ZShelper

**ZShelper — Windows-прототип помощника для голосовых запросов и ограниченных системных действий.**
В приложении есть Tauri/React UI, Rust-ядро, планировщик, системные средства речи, журнал, память,
сценарии и 56 исполняемых рук. Это **не универсальный агент и не готовый к массовому релизу продукт**:
каталог содержит 835 строк, но лишь 56 привязаны к исполнению; профили приложений описывают операции,
но не превращают их автоматически в работающую автоматизацию.

> Лицензирование и серверные компоненты не входят в текущую сборку. Работа не всегда локальна:
> распознавание/синтез речи могут использовать службы Windows, а подключённые модели и действия
> наружу зависят от выбранных endpoint и инструментов. См. [`SECURITY.md`](SECURITY.md).
> Стек: Tauri 2 + Rust + React/Fluent UI ([решение](docs/DECISION-STACK.md)).

---

## Статус готовности

**Стадия: прототип / ранняя альфа, не production-ready.** Frontend typecheck, unit-тесты, генераторы,
Windows-компиляция и сборка установщиков проверяются в CI. Последняя сводка и количественные метрики —
[`docs/DASHBOARD.md`](docs/DASHBOARD.md); блокирующие пробелы и критерии релиза —
[`docs/READINESS-AUDIT.md`](docs/READINESS-AUDIT.md).

Ключевые ограничения сейчас: нет живой приёмки на разных Windows-машинах; 15 обязательных eval-сценариев
пока план, а не полный успешный прогон; нет updater с подписанным манифестом, Authenticode-подписи,
отзыва уязвимых релизов и гарантированно локальных ASR/TTS; MCP-коннекторы не являются готовой функцией.
Опасные действия ограничены правилами и подтверждениями, но перечень рук конечен и явно описан.

## Запустить

```powershell
npm ci
npm run dev             # UI в браузере; системные Windows-функции здесь недоступны
npm test                # Vitest + тесты проверки release-манифеста
npm run tauri dev       # desktop-приложение (Windows SDK/Rust/WebView2)
```

Сводка разработки: [`docs/DASHBOARD.md`](docs/DASHBOARD.md). План: [`docs/ROADMAP.md`](docs/ROADMAP.md).
Инструкции разработчика: [`docs/BUILD-GUIDE.md`](docs/BUILD-GUIDE.md); пользовательская инструкция:
[`docs/GUIDE.md`](docs/GUIDE.md).

## С чего начать

**[`docs/BUILD-GUIDE.md`](docs/BUILD-GUIDE.md) — инструкция по сборке приложения**: если задача —
«писать код», начинать с него, а не с этого файла.

**[`docs/GUIDE.md`](docs/GUIDE.md) — инструкция для человека за компьютером**: что нажимать,
как читать результат руки и что делать, если она отказала.

**[`AGENTS.md`](AGENTS.md) — единственная точка входа**: состояние проекта (генерируется из данных),
карта всех артефактов, маршрут чтения на 20 минут, пять рецептов добавления данных, инварианты и
мёртвые концы. Написан так, чтобы человек или модель без контекста поняли проект и смогли
продолжить работу, не спрашивая предысторию.

## Ключевые идеи продукта

1. **Ансамбль мелких моделей, а не одна большая.** ASR, VAD, wake-word, TTS, OCR, VLM,
   embeddings, reranker, «роутер» 0.6–1.7B, «мозг» 4–8B, «кодер», «критик» — каждая под свою роль.
2. **Автоподстройка под железо.** Профилировщик (статика + калибровка) → tier T0…T3 → набор
   моделей, квантов, контекста, потоков и лимитов. Потолки: ≤60 % RAM, ≤70 % VRAM, пауза в играх.
3. **Оркестратор с реестром способностей.** Планировщик видит 8–15 релевантных инструментов
   (не 60), выбирает скилл-рецепт или строит план; каждый шаг проходит policy gate.
4. **Руки и глаза с проверкой.** UIA-дерево → OCR → VLM (в таком порядке). Координаты кликов —
   только из проверяемых источников. После каждого действия — проверка «что изменилось».
5. **Безопасность по умолчанию.** Классы риска `read / write-local / destructive / external /
   money / identity`, подтверждения с показом diff, корзина вместо удаления, снапшоты, аудит,
   Telegram-кнопки «Стоп/Откатить».
6. **Долгие сессии.** SQLite-очередь, идемпотентные шаги, чекпойнты, восстановление после
   краха, бюджеты и heartbeat — «работай, пока не сделаешь».
7. **Одна кодовая база — любое железо.** T0 (4 ГБ, без GPU) → T3 (32 ГБ, RTX): лестница из 14
   рычагов (модель → квант → контекст/KV → бэкенд → offload → потоки → кэш префикса →
   спекулятивное декодирование → каскад → сжатие промпта → ОС-настройки → планирование).
   Детали и таблицы конфигов — [`research/notes/17-any-hardware.md`](research/notes/17-any-hardware.md).
8. **Кодинг-агент как ядро пользы.** Бриф → исследование с источниками → план → реализация
   в git-worktree → тесты → отчёт → «как продолжить завтра».

## Быстрый старт (исследовательская часть)

```bash
# обновить/дозакачать источники (нужен GitHub token для больших лимитов)
GITHUB_TOKEN=$(gh auth token) python3 tools/collect_sources.py fetch

# найти новое по 30 запросам
GITHUB_TOKEN=$(gh auth token) python3 tools/collect_sources.py discover

# пересобрать индексы
python3 tools/shortlist.py && python3 tools/collect_sources.py index
```

Требования: Python 3.11+, `git`, `gh` (для токена). Никаких зависимостей ставить не нужно —
скрипты на стандартной библиотеке.

## Принципы

- **Local-first.** Базовая функциональность работает без интернета.
- **Least privilege.** Инструмент без объявленных прав не вызывается.
- **Everything is a tool call.** Всё, что меняет мир, проходит через реестр, политику и аудит.
- **Честные границы.** Агент говорит «не могу» вместо «сделал» (и подтверждает результат).
- **Деградация, а не отказ.** На слабом ПК — меньше моделей и возможностей, но работает.

## Дисклеймер

Это прототип, который может выполнять перечисленные в интерфейсе действия на компьютере.
Он запрашивает подтверждение для опасных операций и пишет журнал, но отмена процесса не отменяет
уже совершённый побочный эффект, а откат поддерживает только часть операций. Не отключайте
подтверждения и держите резервные копии важных данных.
