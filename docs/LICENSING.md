# Лицензирование и защита от пиратства: спецификация

Спутник: [`research/notes/29-licensing-and-antipiracy.md`](../research/notes/29-licensing-and-antipiracy.md)
(там модель угроз, экономика и юридическая часть). Здесь — как это устроено технически.

**Коротко:** Ed25519-токены, привязанные к устройству, TTL 72 часа, офлайн 7 дней + grace 7 дней,
ценность (пакеты умений) на сервере, в клиенте — ни одного секрета.

---

## 1. Модель данных и форматы

### Ключ продукта

```
ZSH-XXXX-XXXX-XXXX-XXXX        # base32, 20 значащих символов ≈ 100 бит энтропии
```

- Генерируется сервером после оплаты (или импортом пачки для ручных продаж).
- В БД хранится **не ключ**, а `key_hash = argon2id(key, pepper)`: утечка БД не даёт рабочих ключей.
- Формат не кодирует ничего (никаких «первых 4 символов = тариф») — иначе ключи угадываются.

### Типы лицензий

| Тип | Период | Устройств | Экспорт | Пакеты умений |
| --- | --- | --- | --- | --- |
| `trial` | 14 дней | 1 | водяной знак | базовые |
| `pro` | 1 мес / 1 год | 2 | без знака | про |
| `team` | 1 мес / 1 год | 5 | без знака | про + командные |
| `lifetime` | бессрочно (тот же протокол, `period_end = null`) | 2 | без знака | про |
| `nfr` (пресса/партнёры) | 1 год | 1 | знак | про |

### Токен лицензии

Ed25519-подпись над JSON (см. заметку 29 §3.1). Кэш: `%LOCALAPPDATA%\ZShelper\license.tok` +
дубликат в защищённом хранилище (DPAPI), чтобы удаление файла не «продлевало» триал.

## 2. Потоки

```
ПОКУПКА
  клиент → лендинг → платёжный провайдер (MoR) → вебхук paid → сервер выпускает ключ → письмо

АКТИВАЦИЯ (первый запуск с ключом)
  клиент: fingerprint = sha256(salt‖MachineGuid‖board‖tpm_pub)
  POST /v1/activate {key, fingerprint, device_name, app_version}
  сервер: ключ → лицензия; seats? → создаёт activation; подписывает токен
  клиент: проверяет подпись, сохраняет токен, скачивает пакеты умений

ПОВСЕДНЕВНО
  запуск: офлайн-проверка подписи + exp + dev
  раз в 24 ч (фон): POST /v1/refresh → новый токен
  раз в сутки: GET /v1/revocations (ETag) → если наш ключ отозван → режим «локально, без облака»

ОТКАЗ/ПЕРЕНОС
  кабинет: POST /v1/deactivate {activation_id} → слот освобождается
  повторная активация на новом устройстве — без поддержки
```

## 3. API

| Метод | Путь | Тело | Ответ |
| --- | --- | --- | --- |
| POST | `/v1/activate` | `{key, fingerprint, device_name, app_version}` | `{token, entitlements[], packs[]}` |
| POST | `/v1/refresh` | `{token}` | `{token, entitlements[]}` |
| POST | `/v1/deactivate` | `{token, activation_id}` | `{ok}` |
| GET | `/v1/entitlements` | — (Bearer token) | `{plan, feats[], packs[]}` |
| GET | `/v1/packs/{id}` | — (Bearer token) | бинарь (ChaCha20-Poly1305, ключ из лицензии) |
| GET | `/v1/revocations` | — | `{keys_hash[], updated_at}` (ETag) |
| POST | `/v1/telemetry` | `{events[]}` | `{ok}` |
| POST | `/webhooks/payment` | провайдер | `{ok}` |

Ошибки: `409 seats_exhausted`, `410 license_revoked`, `423 license_expired`,
`401 bad_token`, `404 unknown_key`. Клиент показывает человеческий текст, не код.

**Rate-limit:** `/activate` — 5/мин на IP и 20/сутки на ключ; `/refresh` — 10/час на токен.

## 4. Схема БД

```sql
licenses(id, key_hash, plan, status, period_end, seats, created_at, note)
  -- status: active | grace | expired | revoked
activations(id, license_id, device_hash, device_name, os, app_version,
            first_seen, last_seen, revoked_at)
payments(id, license_id, provider, provider_ref, amount, currency, kind, created_at)
events(id, license_id, kind, meta_json, ip_hash, created_at)
  -- kind: activated | refreshed | anomaly | revoked | reactivated | trial_started
packs(id, version, min_plan, sha256, key_id, published_at)
```

Индексы: `licenses(key_hash)` (unique), `activations(device_hash)`, `events(license_id, created_at)`.

## 5. Деградация: что работает без лицензии

| Состояние | Локальные функции | Облако | Обновления | Пакеты | Данные |
| --- | --- | --- | --- | --- | --- |
| Активна | ✅ | ✅ | ✅ | ✅ | ✅ |
| Офлайн ≤ 7 дней | ✅ | ❌ | ❌ | ❌ | ✅ |
| Офлайн 8–14 дней | ✅ (баннер) | ❌ | ❌ | ❌ | ✅ |
| Офлайн > 14 дней | ✅ | ❌ | ❌ | ❌ | ✅ |
| Истекла + grace 7 дней | ✅ | ✅ | ✅ | ✅ | ✅ |
| Истекла | ✅ read-only для новых задач | ❌ | ❌ | ❌ | ✅ полный доступ |
| Отозвана | fallback в trial | ❌ | ❌ | ❌ | ✅ |
| Подделана подпись | ❌ (сообщение) | ❌ | ❌ | ❌ | ✅ только чтение/экспорт |

Правило, которое нельзя нарушать: **данные пользователя доступны всегда**. Блокируется
только «новая работа» и серверные функции.

## 6. Что в клиенте, а что на сервере

| Компонент | Где | Почему |
| --- | --- | --- |
| Публичный ключ Ed25519 | клиент | проверка подписи офлайн |
| Приватный ключ подписи | VPS (файл 0400 / KMS) | компрометация = выпуск любых лицензий |
| Логика проверки | Rust-ядро, разнесена по 3–4 местам | нельзя вернуть одну функцию в `true` |
| Промпты, профили, каталог моделей | пакеты умений (шифрованы) | крякнутая копия бесполезна |
| Секреты платёжного провайдера | только VPS | в клиенте их не должно быть вовсе |
| Водяной знак `lic_id` | клиент (встраивает) | атрибуция утечек |

## 7. Защита сборки (CI)

1. `strip` символов, LTO, `panic=abort`, `codegen-units=1`.
2. Проверка «нет секретов»: `grep -a` по бинарнику на `sk_live`, `BEGIN PRIVATE`, `api_key`.
3. Самопроверка целостности: хэш exe сверяется с подписанным манифестом релиза.
4. `WinVerifyTrust` для собственного бинарника и плагинов.
5. Обфускация строковых констант, относящихся к лицензированию.
6. MSIX + подпись Authenticode; публикация через GitHub Releases с Ed25519-манифестом.
7. Отдельный «хардненный» профиль сборки: `--features release-hardening` (без devtools,
   без `--allow-*` из CLI, без подробных логов в проде).

## 8. Тесты (добавить в eval-план)

| Сценарий | Ожидание |
| --- | --- |
| Активация на 3-м устройстве | `409`, понятное сообщение, ссылка на кабинет |
| Перенос на новый ПК | старый слот освобождён, новый работает |
| Офлайн 10 дней | работает с баннером, облако недоступно |
| Перевод часов назад | триггер онлайн-проверки, не продление |
| Подмена `license.tok` | отказ, данные доступны в read-only |
| Отзыв ключа (возврат) | переход в trial, без потери данных |
| Один ключ, 20 отпечатков за сутки | флаг аномалии в админке, ключ не блокируется автоматически |
| Удаление `license.tok` и реестра | триал не «продлевается» |

## 10. Порядок реализации

1. **M1.5 (2–3 дня):** сервер-заглушка `/activate` + `/refresh`, Ed25519, Postgres, локальный тест.
2. **M2 (3–4 дня):** клиентская часть (активация, кэш, офлайн-grace, экран «Лицензия»).
3. **M2.5 (2 дня):** вебхук оплаты, выпуск ключей, письмо, кабинет (деактивация).
4. **M3 (2 дня):** пакеты умений: шифрование, выдача по лицензии, версия и `min_plan`.
5. **M6 (2 дня):** подпись, MSIX, релизный hardening-профиль, проверки в CI.
6. **M8:** телеметрия аномалий, канареечные ключи, водяные знаки в экспортах.
