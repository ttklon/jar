## Следующая ручная проверка: локальный микрофон

Не отмечено выполненным: нужен настоящий Windows/WebView2 и устройство ввода.

1. Открыть Voice без нажатий: нет запроса разрешения или захвата.
2. Нажать «Проверить микрофон локально», разрешить доступ, говорить 3 секунды:
   есть численные длительность/уровень/пик, результат не обещает ASR.
3. Повторить с тишиной/отключённым устройством/запрещённым разрешением:
   честный низкий уровень, недостаток кадров или причина отказа.
4. Отменить во время запроса разрешения, затем разрешить: поток сразу закрыт,
   результат не меняется. Повторить уходом на другой экран и закрытием приложения.
5. Во время теста Ctrl+Space не открывает второй захват; при разговорной записи
   диагностическая кнопка недоступна. После завершения теста проверить фоновый
   Ctrl+Space и обычную запись отдельно.
6. Убедиться по индикатору устройства, что микрофон отпущен при успехе, отказе,
   отмене и уходе; проверить отсутствие аудиофайлов и сетевых вызовов диагностики.

## Автоматизированная симуляция (не ручной desktop acceptance)

`e2e/voice.pw.ts`, команда `npm run test:voice-simulation`, отдельная job Windows
Chromium. Семь сценариев: два хода диалога, локальная диагностика, отмена без ASR,
ошибка ASR с повтором, запрет микрофона, имитированное глобальное удержание,
отмена задержанного ответа ASR через Esc после отпускания кнопки.
Виртуальное устройство подаёт тон через настоящий Chromium media/audio stack;
на границе `transcribe_local` проверяется полученный WAV. ASR/LLM/TTS и события
Tauri подменены явно в `e2e/voice-harness.tsx`. Данные пользователя не используются.
Флаги виртуального устройства и mockIPC не попадают в релизную точку входа.

Это делает голосовой контур воспроизводимо проверяемым без физического микрофона,
но не превращает Chromium в WebView2 и не доказывает точность реального whisper.
Ручные пункты выше сохраняются как отдельный уровень доказательств, а не блокируют
запуск автоматизированных симуляций.
