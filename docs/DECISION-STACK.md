# Решение по стеку: Tauri 2 + Rust-ядро + React/Fluent UI

Статус: **принято** · Дата: 2026-11-08 · Заменяет: «Electron как целевая платформа»
Подробное обоснование и цифры — [`research/notes/28-stack-choice.md`](../research/notes/28-stack-choice.md).

---

## Контекст

ZShelper — Windows 10/11 приложение по подписке: голосовое управление, локальные ИИ-модели,
автоматизация интерфейса, OCR, «руки и глаза». Требования, которые влияют на выбор:

1. работа на слабом железе (4–8 ГБ RAM, без GPU) — память и размер установщика имеют значение;
2. код должен быть максимально устойчив к разбору (продукт платный);
3. вид «как настоящее приложение», а не кустарный скрипт;
4. много нативных вызовов Windows (UIA, ввод, экран, COM);
5. локальные модели как отдельные процессы (llama.cpp, whisper.cpp, OCR);
6. автообновления с подписью;
7. разработчик один, знает JS/TS, Python отвергнут по опыту.

## Решение

| Слой | Выбор |
| --- | --- |
| Оболочка | **Tauri 2** (Rust), окно с Mica, трей, кастомный титул-бар |
| UI | **React 19 + TypeScript + Vite**, компоненты Fluent UI React v9, Tailwind для раскладки |
| Ядро | **Rust**: `windows` (Win32/UIA/COM), `enigo`, `xcap`, `ort` (ONNX), `whisper-rs`, `image`, `tokio` |
| ИИ | сайдкары: `llama.cpp`-server, `whisper.cpp`, PaddleOCR, Piper/Kokoro (localhost HTTP) |
| Лицензии | Rust-модуль: `ed25519-dalek`, отпечаток устройства + TPM-ключ (NCrypt) |
| Обновления | `tauri-plugin-updater`, Ed25519-манифест, дельта-обновления |
| Упаковка | **MSIX** (основной) + **NSIS** (portable/офлайн), подпись Authenticode |
| Сервер | VPS: Caddy → Axum (или Fastify) → Postgres; выдача лицензий и пакетов умений |

## Как выглядит запуск у пользователя

Обычное десктопное приложение: `.exe`, окно Win32, иконка в «Пуске», трей, автозапуск,
офлайн-работа, подпись издателя. Внутри окна — компонент WebView2 (Chromium от Microsoft),
а не браузер рядом. Пошаговое описание процесса, зависимости WebView2 и 10 объективных
критериев приёмки — в [`RUNTIME.md`](RUNTIME.md).

## Почему не Electron

- `app.asar` распаковывается одной командой — вся логика, включая проверку лицензии, читается;
- 85–250 МБ установщика и 100–300 МБ RAM против 3–15 МБ и 30–80 МБ у Tauri;
- полный Chromium + Node — большая поверхность атак и обязательные срочные обновления.

Electron остаётся допустимым для быстрых прототипов и внутренних инструментов.

## Почему не C# + WinUI 3 (пока)

WinUI 3 даёт максимально нативный вид и лучший доступ к UIA, но:

- IL декомпилируется; защита требует обфускации или NativeAOT (часть рефлексии теряется);
- XAML-разработка медленнее, чем HTML/CSS, при требовании «красиво и быстро».

WinUI 3 остаётся **резервным путём**, если web-UI упрётся в нативность (сложные контролы,
доступность, интеграция с оболочкой).

## Почему не Python

Декомпилируется, тяжело упаковывается, ложные срабатывания антивирусов, слабый вид UI.
Python остаётся языком внутреннего тулинга (генераторы реестра, отчёты, эксперименты).

## Последствия

**Положительные**

- установщик ~10 МБ → выше конверсия скачивания, дешёвые дельта-апдейты;
- лицензия и целостность — в машинном коде, а не в JS;
- модель прав (capabilities) ограничивает окно по умолчанию;
- ядро на Rust быстрее и предсказуемее на слабом ПК.

**Отрицательные / риски**

- нужно освоить Rust (оценка: 2–4 недели до продуктивной скорости при наличии JS-опыта);
- часть npm-библиотек недоступна: `node-pty` → `portable-pty`, `sharp` → `image`/libvips;
- WebView2 обязателен (есть в Windows 11 и в Win10 с обновлениями; нужна проверка при установке);
- MCP-серверы на Node остаются сайдкарами — это нормально, но требует менеджера процессов.

## План миграции (если начнём с Electron-прототипа)

1. Вынести весь UI в отдельный пакет (`apps/ui`) — он не зависит от оболочки.
2. Определить контракт «UI ↔ ядро» (типизированный IPC, один файл схемы).
3. Перенести файловые/системные операции в Rust-команды, начиная с лицензии и настроек.
4. Заменить нативные npm-модули (таблица в заметке 28 §4).
5. Собрать MSIX, подписать, прогнать сценарии из `EVALS.md` (P0/P1).

## Критерии пересмотра решения

- Rust-ядро не позволяет реализовать UIA-автоматизацию без боли (тогда — C#-сайдкар для
  автоматизации, оболочка остаётся Tauri);
- WebView2 даёт нестабильный рендеринг на Win10 (тогда — WinUI 3);
- если релиз нужен «вчера» — допустим Electron-релиз **с полным набором hardening** (§6 заметки 28),
  но это осознанный технический долг с датой возврата.

## Чеклист, который делает приложение «не кустарным»

- [ ] MSIX + подпись Authenticode, издатель виден в свойствах файла.
- [ ] Иконки (все размеры), тёмная/светлая тема, корректный DPI на 125/150/200 %.
- [ ] Нет ни одного слушающего порта; DevTools в релизе закрыты; single-instance работает
      (проверки — [`RUNTIME.md`](RUNTIME.md) §4).
- [ ] Онбординг ≤ 60 секунд: профиль железа → 3 вопроса → готово.
- [ ] Автообновление с changelog и откатом.
- [ ] Человеческие ошибки: причина + что сделать, без стектрейсов.
- [ ] Первый ответ UI < 1 с на 4 ГБ RAM.
- [ ] Удаление приложения не оставляет мусора (данные — по выбору пользователя).
