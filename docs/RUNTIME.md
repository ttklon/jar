# Как ZShelper запускается у пользователя (и почему это не браузер)

Короткий ответ: **это обычное десктопное приложение** — `.exe`, окно, иконка в «Пуске»,
запись в «Программы и компоненты», работа в трее, глобальные хоткеи, автозапуск.
Браузера нет: WebView2 — это **встроенный в окно компонент рендеринга**, а не отдельный
браузер, который открывается «рядом». Ровно так же работает Discord — просто у него внутри
свой Chromium, а у нас Microsoft WebView2.

---

## 1. Что происходит при двойном клике

```
zshelper.exe  ──►  нативное окно Win32 (TAO)
                    └── дочернее окно WebView2  (рисует интерфейс)
                          └── ваши ассеты (HTML/JS/CSS) из ресурсов exe, через внутренний протокол
```

- Окно создаётся **нативным кодом**, а не браузером. Нет адресной строки, нет вкладок,
  нет кнопок «назад/обновить», нет меню браузера, нет «не удаётся открыть страницу».
- Контент грузится **из самого приложения** (`tauri://localhost` / `https://tauri.localhost` —
  виртуальный протокол, его обслуживает exe). **Никакой TCP-порт не открывается**, в браузере
  ничего не появляется, `localhost:1420` существует только в режиме разработки (`tauri dev`).
- В «Диспетчере задач» видно `ZShelper.exe` и несколько `msedgewebview2.exe` (это процессы
  рендеринга, как у Discord несколько `Discord.exe`). Пользователь их не замечает.
- Работает офлайн. Никакой «вкладки» и никакой зависимости от открытого Edge/Chrome.

## 2. Чем это отличается от Electron (по ощущениям пользователя)

| Что видит пользователь | Electron (Discord) | Tauri (ZShelper) |
| --- | --- | --- |
| Ярлык, Пуск, панель задач | ✅ | ✅ |
| Своя иконка, имя процесса | ✅ | ✅ |
| Окно без браузерных элементов | ✅ | ✅ |
| Трей, глобальные хоткеи, автозапуск | ✅ | ✅ |
| Уведомления, перетаскивание файлов | ✅ | ✅ |
| Офлайн-работа | ✅ | ✅ |
| Размер установщика | 85–250 МБ | 3–15 МБ |
| Память в простое | 100–300 МБ | 30–80 МБ |
| Движок рендеринга | свой Chromium | WebView2 (Chromium от Microsoft) |
| Зависимость от системного компонента | нет | **WebView2 Runtime** (см. §3) |

Визуально разницы нет: WebView2 — тот же Chromium, поэтому CSS, шрифты, анимации и
Fluent-компоненты выглядят идентично. Разница только в размере и в том, кто обновляет движок.

## 3. Зависимость WebView2: как закрываем

| Система | Состояние | Что делаем |
| --- | --- | --- |
| Windows 11 (все сборки) | WebView2 предустановлен | ничего |
| Windows 10 21H2+ с Edge | WebView2 уже стоит (приезжает с Edge) | проверяем и пропускаем |
| Windows 10 без WebView2 | редко, но бывает (LTSC, отключён Edge, старые сборки) | установщик доставляет runtime |
| Машины без интернета / корпоративные | онлайн-загрузка невозможна | offline-вариант установщика |

Варианты поставки (`bundle.windows.webviewInstallMode` в Tauri 2):

1. `downloadBootstrapper` — установщик докачивает runtime (маленький, нужен интернет);
2. `embedBootstrapper` — bootstrapper внутри установщика (+1.8 МБ);
3. `offlineInstaller` — полный офлайн-установщик WebView2 (+~130 МБ, только для «сложных» случаев);
4. `fixedRuntime` — своя копия WebView2 внутри приложения (+~130 МБ, полный контроль версии).

**Наше решение:** основной MSIX/NSIS — `embedBootstrapper` (интернет обычно есть),
и отдельная «offline» сборка для корпоративных/изолированных машин.
Наличие runtime проверяется через API `GetAvailableCoreWebView2BrowserVersionString`
(или ключи EdgeUpdate) — и это отдельное действие в реестре, с проверкой результата.

## 4. Что проверяет приёмка M1 (объективные критерии)

- [ ] В установленной версии **нет ни одного слушающего порта** (`Get-NetTCPConnection`).
- [ ] `F12`/`Ctrl+Shift+I` в релизе **не открывают** DevTools (в dev — открывают).
- [ ] Правый клик «Просмотреть код» отсутствует; выделение текста интерфейса отключено.
- [ ] Приложение запускается **двойным кликом без интернета** и работает.
- [ ] Второй запуск не открывает второе окно — фокус на существующем (single-instance).
- [ ] Иконка в панели задач, закрепление, Jump List, «Закрыть в трей» — работают.
- [ ] Установка/удаление через MSIX не оставляет мусора (данные — по выбору пользователя).
- [ ] В «Свойствах файла» виден подписант (издатель), SmartScreen не пугает после прогрева репутации.
- [ ] Процесс виден как `ZShelper.exe` с вашей иконкой, без консольного окна.
- [ ] Окно корректно на 125/150/200 % DPI и на двух мониторах.

## 5. Как убедиться за один день (спайк, до основной разработки)

1. ✅ Сборка **release** идёт в CI (`job release` в `.github/workflows/app.yml`):
   `tauri build` собирает установщик NSIS и падает, если тот не появился.
2. ✅ Один экземпляр: `tauri-plugin-single-instance` показывает уже открытое окно вместо
   второго трея, второй горячей клавиши и второго писателя журнала.
3. ⏳ `Get-NetTCPConnection -OwningProcess <pid>` на живой машине — порты не слушаются
   ничем, кроме dev-сервера, но проверить можно только глазами.
4. ⏳ Офлайн-запуск: внешних запросов в коде нет, но проверка — руками на машине без сети.
5. ⏳ Установщик собирается (NSIS); установка, ярлык и удаление — руками. MSIX не
   поддерживается Tauri 2, поэтому цель — NSIS/MSI (см. `DECISION-STACK.md`).

## 6. Частые вопросы

**«А если у пользователя нет WebView2 и нет интернета?»**
Отдельная offline-сборка (вариант 3 или 4). Это редкий случай, но мы его закрываем.

**«А WebView2 не обновится и не сломает мне интерфейс?»**
WebView2 обновляется как Edge — плавно и совместимо. Если нужна фиксированная версия
(например, для enterprise-клиента) — `fixedRuntime`.

**«Это будет выглядеть как сайт?»**
Нет: окно нативное, а внутри — ваши компоненты Fluent UI v9, кастомный титул-бар с Mica,
системные диалоги, контекстные меню Windows, родные уведомления. Пользователь видит
приложение, а не страницу.

**«Можно ли всё-таки открыть это в браузере?»**
Нет, и это плюс: `http://localhost` не слушается, ассеты читаются из ресурсов exe через
внутренний протокол, доступ к файловой системе — только через явные Rust-команды с правами
(capabilities).
