## M1 · Скелет приложения и «руки» (2–3 недели)

- [x] **Tauri 2 + React 19/TS strict** (решение — [`DECISION-STACK.md`](DECISION-STACK.md)): окно, трей, capability-манифест, иконки
      генерируются скриптом, сборка UI проверяется в CI (`src-tauri/`, `src/`)
- [x] Глобальная клавиша `Ctrl+Alt+Z`: показывает и скрывает окно из любой программы; действий не выполняет — подтвердить что-то за человека клавиша не может
- [ ] Mica-эффект окна: включать только там, где видно результат
- [x] Rust-ядро: команды IPC (`registry_snapshot`, `app_status`), логирование в
      `%LOCALAPPDATA%\ZShelper\logs`, тесты реестра (`cargo test`)
- [ ] Менеджер сайдкаров (llama.cpp/whisper.cpp)
- [x] Release-сборка и установщик NSIS в CI (`job release`), single-instance
- [ ] Остаток спайка: проверить на живой машине, что порты не слушаются, офлайн-запуск
      и установка/удаление работают (см. [`RUNTIME.md`](RUNTIME.md) §5)
- [x] SQLite-память (`memory.rs`): `runs`, `steps`, `facts`, миграции через
      `PRAGMA user_version`; удачные параметры подставляются в интерфейс
- [x] Активное окно (`window.rs`): заголовок, программа и PID того, что перед человеком.
      Только чтение — ни клика, ни переключения. Спрашивается в момент, когда человек
      заговорил, и показывается на экране; в браузере окон системы нет, и это сказано прямо
- [x] Окно в самой задаче (`context.ts`): подсказка про программу перед человеком поднимает
      свои руки наверх, решения и опасность не меняются, незнакомая программа порядок не
      трогает, и экран говорит, что именно учтено
- [x] Память фактов (`memory::facts` + `lib/facts.ts`): сказанное раньше подставляется в
      вопросы плана, помечено как «из памяти» и переписывается одним движением. Пустое не
      запоминается, забыть можно, вопрос о забытом не задаётся второй раз
- [x] Вопрос к модели и строгий разбор её ответа (`intent.rs`): один объект JSON четырёх
      видов (call / learn / ask / refuse), выдуманная рука отвергается, два ответа — не выбор,
      а ошибка. Вопрос собирается из задачи, окна, памяти и найденных рук и показывается
      человеку целиком — без «доверьтесь нам». Сам вызов модели ещё не подключён
- [x] Вызов модели (`llm.rs` + `think`): один POST на петлю `127.0.0.1`, таймаут, разбор
      `choices[0].message.content`, chunked-ответ, отказ движка своими словами. Ответ
      разбирается `intent::parse` и показывается человеку; ничего не выполняется. Наружу
      ничего не уходит — это видно по адресу и проверено тестом на своём сервере на петле
- [x] Выбор модели не в обход (`plan::chosen`): `call` становится обычным планом — та же
      политика, те же вопросы, то же подтверждение. Выдуманный параметр отбрасывается, выбор
      без руки прямо называется описанием, а не делом
- [x] «Не умею» оставляет след (`learn::request_for_goal`): модель называет цель — просьба
      записывается в память, повтор поднимает её в очереди, карточка обучения видна на экране
      и переживает перезапуск. Цель без строки в реестре прямо называется невыполнимой
- [x] Черновик руки (`hand.rs`): модель пишет скрипт, фильтр отсеивает сеть, `iex`, повышение
      прав, секреты и необратимое удаление, черновик сохраняется и показывается человеку.
      Пути к исполнению у него **нет**: ни из плана, ни из рук. Фильтр — не песочница, и это
      сказано прямо, поэтому между «похоже на безопасное» и «исполнено» стоит человек
- [x] Проба черновика в клетке (`trial.rs`): запуск с потолками и коротким сроком, отчёт с
      кодом, выводом и пометкой, где это было. Клетка не открылась — проба **не выполняется**
      и говорит это прямо: чужой текст без забора не запускается. Отчёт не делает черновик
      умением
- [x] Привнесённые руки (`custom.rs`): проверенный черновик принимается **по слову человека**,
      хранится отдельно от встроенных, виден списком с кодом и опасностью, убирается одной
      кнопкой. Исполнения у них нет: ни реестра, ни плана, ни `tools::spec`
- [x] Запуск своей руки (`trial::run_required`): только в клетке, только по слову человека,
      только с отчётом. Клетка не открылась — **отказ**, а не «запуск без забора». Пробу и
      запуск не путаем: они хранятся раздельно, иначе теряется доказательство приёма. В планы
      привнесённые руки по-прежнему не попадают — автоматики нет
- [x] Модель подключается сама (`Voice.search`): если поиск по словам ничего не нашёл,
      фраза уходит модели вместе с окном перед человеком; её план показывается как обычный,
      её обучение — карточкой. Движок не ответил — фраза не пропадает, идёт в обучение
- [x] **Очередь дел:** `src/lib/queue.ts` — несколько задач подряд по бюджету машины.
      Идёт сама только когда человек отошёл; план, которому нужно подтверждение или ответ,
      помечается «нужно ваше слово» и не исполняется; «стоп» останавливает не начатое.
      Логика чистая и проверена без окон: 11 тестов модуля + 3 экранных
- [x] **Машина:** `machine.rs` измеряет загрузку процессора, свободную память и простой
      ввода, и говорит, сколько дел можно вести сразу (`near`/`away`/`crowded`) — с причиной,
      а не числом. Мало памяти — это «новое не начинать», а не «помедленнее»
- [x] **UI Automation, только чтение:** `uia.rs` разбирает активное окно по элементам —
      вид, имя, идентификатор, доступен ли, какие действия окно объявило. Потолки (400
      элементов, глубина 12) с честным признаком «дерево обрезано». Текст экрана уходит
      модели вместе с вопросом, и человек видит ровно тот же текст
- [x] **Нажатие по элементу:** `uia::press` находит элемент по имени (точное совпадение
      важнее вхождения, несколько подходящих — отказ, а не лотерея), требует объявленного
      `invoke`, нажимает и **проверяет** результат сравнением элементов до и после. В
      интерфейсе — два шага: «нажать „Войти“?» и «Да, нажать»; в журнал пишется и «нажато,
      но экран не изменился»
- [x] **Ввод текста в поле:** `uia::type_text` находит поле по имени, требует `value`,
      вводит и **читает обратно** — «введено» это «поле показывает то же», а не «отправили».
      Маска или проверка, изменившие текст, видны в отчёте. В интерфейсе: поле ввода,
      подтверждение, итог; в журнал идёт вид поля и результат, но не сам текст
- [x] **Нажатие и ввод как шаги плана:** `apps-windows|нажать|кнопку` и
      `apps-windows|ввести|текст` объявлены в `data/tools.json` и исполняются
      `tools::run`; риск `destructive`/`write-local` → подтверждение политикой и токен.
      Доказательство нового вида — `ui_changed`: «нажато, но ничего не изменилось»
      считается **невыполненным** шагом, потому что доказательства нет
- [ ] Нативный слой: скриншот, клик/ввод, проверка после действия (**прототип Rust**)
- [x] Реестр `data/actions.json` загружается как каталог инструментов: индексы по `id` и
      `domain|verb|object`, статистика, поиск, экран «Что умею» с фильтром риска
- [x] Первые исполняемые инструменты (`data/tools.json`): создание папки, размеры, поиск, дубликаты, процессы, диски, SMART, сеть, порты, корзина — с проверкой результата; перемещение без перезаписи, запуск программы с проверкой процесса, список установленных программ, автозапуск, батарея, характеристики железа
- [x] Сценарии (`data/flows.json`): 7 процедур из 21 шага — «как поживает компьютер», «что в этой папке», «освободи место», «создай папку проекта», «почему нет интернета», «что запускается само», «что за компьютер»; остановка на провале, подтверждение опасного шага, валидатор `tools/flows.py`
- [x] Загрузчик профилей: сводка `data/profiles.json` (87 приложений, 547 операций),
      экран «Приложения» с поиском и честной отметкой, что из этого уже исполняется
- [ ] Движение по шагам профиля с обязательной верификацией (`tools/profiles.py` уже
      валидирует данные; нужен слой автоматизации интерфейса — UIA)
- [ ] `tools/uia_probe.py`: авто-профиль из UIA-дампа (tier B) + визуальный агент как fallback (tier C)
- [x] Экран «Спросить»: «что нужно сделать?» своими словами — поиск по реестру, риск и
      решение политики у каждого найденного действия, отметка выполнимости
- [x] Экран «История»: читает `audit.jsonl` (последние 100 событий, битые строки пропускаются) — видно, что просили, что решила политика и чем закончилось
- [x] Policy engine: `read` выполняется, изменение требует одноразового подтверждения, `identity`/`money`/`never` — отказ; журнал `audit.jsonl`; диалог подтверждения в UI
- [x] Статика железа: `hardware-diag|показать|характеристики железа` — процессор, память,
      видеокарты, накопители, версия Windows; плюс сценарий «Что за компьютер»
- [ ] Калибровка железа: замеры под нагрузкой и рекомендации под выбор модели (следующий шаг, нужен планировщик)

**Выход:** «создай папку», «удали в корзину», «открой приложение» — работают, всё логируется,
опасное переспрашивает.

## M2 · Голос (2 недели)

- [x] Главный экран — голос: приложение открывается микрофоном, а не списком экранов;
      реестр, руки, сценарии и история уезжают «под капот» (два входа в одно место —
      кнопка в меню и ссылка с голосового экрана)
- [x] Удержание: зажал кнопку (или Ctrl+Space) — слушаем, отпустил — разбираем.
      Хоткей не срабатывает, когда человек печатает в поле: пробел остаётся пробелом
- [x] Удержание из **любой** программы (`hotkey.rs` + `globalTalk.ts`): `Ctrl+Space` ловится
      глобально, окно показывается без перехвата фокуса, в интерфейс уходят два события —
      «нажал» и «отпустил». Если клавишу заняла другая программа, это видно в журнале, а
      разговор из своих окон продолжает работать кнопкой
- [x] Первый шаг голоса: кнопка «Держать и говорить» на экране «Спросить», услышанная фраза идёт
      в тот же поиск, что и напечатанная, итог плана проговаривается вслух. Работает на
      том, что уже есть в окружении (WebView2/Chromium + синтез системы), поэтому звук
      покидает компьютер — это написано рядом с кнопкой, а не в документации
- [x] Свой движок распознавания: `stt.rs` — поиск `whisper-server.exe`, флаги, multipart
      на `/inference` руками, разбор ответа, остановка процесса после запроса. Готовность
      движка проверяется открытием порта, а не догадкой про `/health`
- [x] Статус распознавания на главном экране: есть движок и модель или нет, и куда
      положить файлы. Пока своего движка нет — прямо сказано, что звук уходит наружу
- [x] Запись звука в интерфейсе: `wav.ts` (моно, 16 бит, приведение частоты усреднением,
      обрезка тишины по краям) и `recorder.ts` (граф, накопление кусков, остановка
      микрофона). Есть движок — держим кнопку, пишем, отдаём ему; нет — слушаем системой
- [x] «Слушаю всегда» (`vad.ts` + `useVoice`): микрофон открыт, начало и конец фразы
      решает громкость с гистерезисом, короткий щелчок не считается речью, пауза между
      словами не рвёт фразу, забытый микрофон закрывается по пределу длины. Каждый кусок
      проверяется на компьютере; работает со своим движком, и об этом сказано прямо
- [x] Ответ на уточняющий вопрос голосом: у каждого вопроса есть «сказать ответ»,
      услышанное заполняет поле (а не уходит в новый поиск), приложение говорит вслух, что
      услышало, и задаёт следующий вопрос тоже вслух. Пустой разбор — честная ошибка, поле
      остаётся пустым, а не заполняется догадкой
- [x] Отправка по паузе в удержании (`useVoice` сегменты): говоришь фразу за фразой, кнопку
      держишь, пока думаешь; отпустил — текущая фраза заканчивается и уходит. Работает только
      со своим движком: паузу вырезает `vad`
- [x] Отмена записи (`useVoice.cancel`): «нет, не то» выбрасывает запись — без разбора, без
      ошибки и без фразы в поле. `Esc` во время слушания, кнопка «Отмена», а в режиме «слушаю
      всегда» отменяется только текущая фраза: микрофон продолжает слушать
- [ ] Свой путь без облака: WASAPI-захват, Silero VAD, whisper.cpp — тогда звук остаётся
      на диске и это станет путём по умолчанию
- [ ] WASAPI-захват и Silero VAD в ядре вместо простого порога: шум улицы не должен
      запускать фразу, а тихая речь у микрофона — теряться
- [ ] whisper.cpp (turbo Q5) + словарь-промпт, двухпроходный ASR
- [ ] TTS: Kokoro/Piper, очередь по предложениям, barge-in
- [ ] Машина состояний аудио, «стоп» в audio-воркере
- [ ] Wake-word (опция, русская фраза)

**Выход:** голосовой сценарий «услышал → сделал → сказал» с латентностью ≤ 1.5 с (p50).

**Как это должно ощущаться (замысел, к которому идём):** человек ничего не выбирает в
интерфейсе. Он говорит «сделай то-то» — приложение отвечает, уточняет, проговаривает,
что делает, и делает. Один экран — микрофон; реестр, руки, сценарии и журнал остаются
внутри как доказательство, а не как рабочий стол.

**Если руки нет — три честных состояния шага.** Сейчас в реестре два: «умею выполнить»
и «умею только описать». Замысел добавляет третье: «умею через интерфейс программы»
(UI Automation: нажать кнопку в чужом окне, если у приложения нет API). Порядок попыток
всегда один и тот же — свой инструмент, затем интерфейс программы, затем честный отказ
с описанием, что именно человек может сделать сам.

## M3 · Мозги (3 недели)

- [x] Модели на диске (`models.rs`): папка моделей (`%LOCALAPPDATA%\ZShelper\models` или
      `ZSHELPER_MODELS_DIR`), чтение заголовка GGUF (версия, архитектура, квантование,
      число тензоров), экран «Модели» с честным «файл прочитан» вместо «модель готова»
- [x] Сверка хеша модели (`sha2`): файл читается потоком, хеш `model.sha256:<файл>`
      запоминается в памяти и сравнивается при следующей сверке — так видно подмену и
      битую докачку. Эталонных хешей в манифесте пока нет, и интерфейс говорит именно
      «тот же, что и в прошлый раз», а не «проверено»
- [x] Скачивание модели (`download.rs`): системный `curl`, `.part` → sha256 → атомарное
      переименование; недокачанный или несошедшийся по хешу файл удаляется целиком,
      существующий файл не перезаписывается без спроса; экран «Модели» спрашивает ссылку
      и необязательный эталонный sha256 (проверяется на локальном HTTP-сервере в тестах)
- [x] Место и удаление (`models.rs`): занятое моделями и свободное на диске (PowerShell,
      `Get-CimInstance Win32_LogicalDisk`), удаление файла только после подтверждения в

      требование к роли (потолок размера) и привязка к файлу, который уже лежит на диске;
      назначение живёт в памяти, назначить несуществующий файл нельзя, слишком большая
      модель называется слишком большой, а не «плохой»
- [ ] Менеджер моделей: манифест с эталонными sha256, зеркала, LRU
- [x] Эпизоды в памяти (`Memory::search`): поиск по прошлым запускам, где каждое слово
      запроса обязано найтись в предмете, шаге или доказательстве, а ответ называет
      совпавшие слова. Ищет в последних 2000 запусках — предел назван, а не спрятан
- [x] Запуск плана (`run_plan`): шаги по порядку, один запуск в памяти, отчёт по шагам.

      **до** первого шага: план либо начинается целиком, либо не начинается вовсе
- [x] Схема плана и валидатор (`plan.rs`): JSON с `goal` и `steps[].registry`; каждый шаг
      обязан существовать в реестре, иметь «руку», не быть запрещённым политикой и нести

- [x] Черновик плана без модели (`plan::draft`): один шаг из реестра, у которого есть
      рука и который не запрещён, плюс данные из памяти прошлого запуска. Не хватает
      данных — план говорит, каких, и не даёт себя выполнить
- [x] Задача на обучение (`learn.rs`): на просьбу, которую приложение не умеет, оно

      пока рука не написана
- [x] Проверка перед запуском (`sandbox.rs`): статический экран текста команды (диски,
      учётные записи, реестр, сеть, повышение прав, обфускация), экран значений
      параметров (вторая команда в значении) и пробный запуск в отдельной папке с
      таймаутом. Отдельный тест требует, чтобы собственные руки проходили собственные

- [x] Потолки запуска (`isolation.rs`): job object на Windows — не больше 256 МБ памяти,
      5 с процессорного времени и 8 процессов на пробный запуск, и смерть всего дерева
      при закрытии объекта. Пробный запуск (`sandbox::trial`) идёт под ними; два теста на
      Windows проверяют, что бесконечный цикл останавливает потолок, а не таймаут, и что
      жадный до памяти процесс упирается в потолок. Экран говорит, что потолки есть
- [x] Ограниченный токен (`restricted.rs`): `CreateRestrictedToken` со снятыми привилегиями
      и администраторами «только для отказа», запуск через `CreateProcessAsUserW` с

      идёт без прав; тест на Windows требует, чтобы у ограниченного процесса не осталось
      ни одной привилегии, кроме `SeChangeNotifyPrivilege`, а у обычного — остались
- [~] Забор для файлов попыткой ограничивающих SID — **не вышло, честно записано**:

      не запускается вовсе: код `0xC0000142` (`STATUS_DLL_INIT_FAILED`), ещё до первой

      библиотек нужен ещё и реестр пользователя. Два прогона CI, обе попытки с этим кодом;

- [~] Забор и сеть через **AppContainer** (`container.rs`): профиль контейнера, его SID,

- [ ] Пока клетка не открылась, пробный запуск идёт с ограниченным токеном, а в отчёте
