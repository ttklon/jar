# Roadmap — ZShelper

Статус: **M0 — исследование** (этот этап). Ниже — план по этапам с критериями выхода.
Оценки — в «человеко-днях» одного агента, не календарные обещания.

## M0 · Исследование и фундамент ✅ (текущий)

- [x] Vault источников: ~740 репозиториев/пакетов, ~16 МБ текстов, `research/INDEX.md`
- [x] Инвентаризация MCP: ~1470 серверов, каталогизация по доменам (`research/discovery/`)
- [x] Конспекты по 16 направлениям (`research/notes/00…16`)
- [x] Требования разложены на R-01…R-28
- [ ] Проверить ключевые технические гипотезы на прототипах (см. M1)

**Выход:** можно начинать код, нет «слепых зон» в архитектуре.

## M1 · Скелет приложения и «руки» (2–3 недели)

- [ ] Electron + electron-vite + TS strict, окно, трей, хоткеи, `utilityProcess`-ядро
- [ ] SQLite-схема (events/jobs/steps/audit/facts), миграции
- [ ] Нативный слой: скриншот, UIA-дамп, клик/ввод, проверка после действия (**прототип Rust**)
- [ ] Реестр способностей + 10 встроенных инструментов
- [ ] Policy engine (3 режима) + аудит + подтверждение в UI
- [ ] Профилировщик железа (статика + калибровка)

**Выход:** «создай папку», «удали в корзину», «открой приложение» — работают, всё логируется,
опасное переспрашивает.

## M2 · Голос (2 недели)

- [ ] WASAPI-захват, Silero VAD, PTT-хоткей, индикатор
- [ ] whisper.cpp (turbo Q5) + словарь-промпт, двухпроходный ASR
- [ ] TTS: Kokoro/Piper, очередь по предложениям, barge-in
- [ ] Машина состояний аудио, «стоп» в audio-воркере
- [ ] Wake-word (опция, русская фраза)

**Выход:** голосовой сценарий «услышал → сделал → сказал» с латентностью ≤ 1.5 с (p50).

## M3 · Мозги (3 недели)

- [ ] Менеджер моделей: манифест, скачивание, sha256, LRU, `llama-server`
- [ ] Router (1.7B, JSON-схема) + Planner (4B/8B) + verifier
- [ ] Retrieval инструментов (BM25 + embed), карточки инструментов
- [ ] Скиллы (формат + 8 первых: папки, окна, браузер, медиа, заметки, календарь…)
- [ ] Память: факты + эпизоды + гибридный поиск

**Выход:** 15 типовых голосовых задач выполняются без ручного вмешательства.

## M4 · MCP и коннекторы (2 недели)

- [ ] MCP-клиент (stdio + Streamable HTTP, обе эры протокола, MRTR, таймауты, лимиты)
- [ ] Свой `windows-mcp` и `media-mcp`
- [ ] Каталог MCP-серверов в UI (установка, права, здоровье)
- [ ] Telegram-алерты с кнопками; Google Calendar (OAuth+PKCE)
- [ ] «ZShelper как MCP-сервер» наружу

**Выход:** «поставь встречу», «отправь мне скриншот в телегу», «скачай и перескажи видео».

## M5 · Кодинг-агент (3–4 недели)

- [ ] Бриф → исследование → отчёт → план → каркас → реализация (worktree, патчи, тесты)
- [ ] Интеграция с `node-pty`, декодирование вывода Windows, таймауты
- [ ] Чекпойнты, восстановление, heartbeat в Telegram, бюджеты
- [ ] Отчёты (markdown + скриншоты), «продолжить завтра»

**Выход:** задача «сделай приложение X» доводится до запускаемого состояния в 70 % случаев.

## M6 · Полировка и релиз (2–3 недели)

- [ ] UI: лента, план, подтверждения, настройки, первый запуск
- [ ] Установщик NSIS + portable, автообновление, миграции
- [ ] CI: lint/test/e2e/security/package/release, SBOM, аттестации
- [ ] Evals-наборы + ночные прогоны
- [ ] Документация пользователя (RU), техдок, SECURITY.md

**Выход:** v1.0 на GitHub Releases, работает на Windows 10/11 на T1 и T2.

## M7+ · После v1

- Wake-word 24/7 с дневником дня и заметками
- Профили приложений (CapCut/Premiere/Photoshop/Excel) как библиотека
- Полный дуплекс (Moshi-класс), клонирование голоса (с согласием)
- arm64, MSIX, автопакеты через winget
- Публичный мини-лидерборд русских desktop-команд

## Риски расписания

| Риск | Влияние | Что делаем |
| --- | --- | --- |
| Нативный слой Windows дольше, чем кажется | сдвиг M1 | прототип на 2 дня первым делом; fallback на nut-js |
| Слабый tool-calling у мелких моделей | качество | retrieval инструментов, JSON-схемы, один инструмент на шаг |
| SmartScreen/антивирус | установка | portable-сборка, документация, подпись позже |
| Компьютер-юз агенты нестабильны (реальность 2026) | ожидания | узкие скиллы с проверками вместо «универсального агента» |
