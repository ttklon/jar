# План на 500 шагов: из работающего прототипа в приложение, которому не нужно верить на слово

**Что это.** Не обещание «станет идеально», а список из 500 проверяемых работ. Каждый шаг
сформулирован так, чтобы у него был видимый результат и способ проверить, что он достигнут.
Где возможно — проверка автоматическая; где нельзя (живая Windows, микрофон, звук в комнате) —
это названо честно и не выдаётся за сделанное.

**Откуда взято.** Сначала — код и документы этого репозитория (что реально есть в
`src/`, `src-tauri/src/`, `data/`, `docs/`), затем — что делают похожие программы
(Raycast, Windows Copilot, PowerToys, Home Assistant, Jan/LM Studio, Ollama,
whisper.cpp/Piper) и почему у них стоит взять именно это, а не всё подряд.
Внешние ориентиры: приём «сначала первый звук, потом остальное», перебивание в пределах
200 мс, перебивание по VAD ~85–100 мс, бюджет «рот → ухо» 500–1100 мс; для локального
стека на CPU честная цель — 1.5 с до первого звука, а 5–10 с ожидания — это уже дефект.

**Чего здесь нет.** Ни одной строки вида «внедрить AGI». Ни одного шага, который нельзя
проверить. Ни одного обещания, которое нельзя опровергнуть тестом, логом или приёмкой.

**Чего приложение пока не умеет — и это не шаг плана, а граница:** живой микрофон,
качество русской речи, офлайн-Windows, WASAPI, Silero, собственный TTS, Authenticode,
полный прожим сторонних программ, семь блокеров [`READINESS-AUDIT.md`](READINESS-AUDIT.md).
Эти пункты можно закрыть только на живой машине или подписью издателя.

**Что это меняет по существу:** «Цель» ещё не второй друг, который всё делает, но
четыре вещи, на которых спотыкались каждый день, больше не спотыкаются: экран
находится с клавиатуры, ошибки слышны, приложение поднимается само, а окно не
превращается в полоску при крупном шрифте. Ни один из этих шагов не требовал
живой Windows — поэтому они и сделаны первыми.

## 1 · Правда о себе: приложение не врёт о своём состоянии

| № | Шаг | Зачем / чем проверяется |
| --- | --- | --- |
| 1 | Свести все состояния «можно/нельзя» в один честный экран `Состояние` | сейчас правда размазана по 10 экранам и README; человек не может узнать одним взглядом, что работает |
| 2 | Ввести словарь состояния: (не установлено / не проверено / проверено на этой машине / провал) | слово «готово» без «где проверено» уже один раз вводило в заблуждение |
| 3 | Хранить вердикт проверки вместе с машиной, ОС, версией приложения | статус «работает» без машины нельзя ни опровергнуть, ни воспроизвести |
| 4 | Показать рядом с каждым экраном строку «на этой машине доказано / не доказано» | человек должен видеть границу до нажатия, а не после |
| 5 | Запретить слову «готово» появляться без даты и области проверки | генератор проверяет текст, а не память автора |
| 6 | Ввести «карту честности»: список обещаний и чем каждое закрыто (тест/лог/приёмка) | это документ, который CI пересобирает из данных, и его нельзя забыть обновить |
| 7 | Каждая рука получает запись: параметры, права, необратимое, отмена, проверка, версии Windows | блокер №2 аудита; без таблицы «умеет» — это реклама |
| 8 | Отдельно пометить руки, где отмена не отменяет уже сделанный эффект | иначе «Стоп» читается как «всё отменилось» |
| 9 | Показывать пустоту явно: «здесь ничего не проверялось», а не пустой список | пустой список выглядит как «всё хорошо» |
| 10 | Тест, который валит сборку, если рука описывает эффект, не указав отмену | требование пользователя: не считать вызов доказательством |
| 11 | Ввести «паспорт руки»: что делает, что не делает, где проверено, кем | один файл — одно обещание |
| 12 | Показывать возраст доказательства: когда последний раз проверяли на этой машине | старое «работало» — не «работает» |
| 13 | Считать «непроверенное» отдельным статусом, а не пустым местом | иначе статус по умолчанию читается как «ок» |
| 14 | Свести все отказы к словарю причин: нет программы, нет прав, нет места, нет сети, нельзя по политике | человек учится один раз |
| 15 | Один и тот же отказ одинаково звучит на всех экранах | разные слова для одной причины — это шум |
| 16 | Пометка «на этой машине не проверено» рядом с кнопкой запуска | не после нажатия |
| 17 | Спрашивать систему о версии Windows/WebView2 и показывать это в «Состоянии» | без этого поддержка — угадывание |
| 18 | Проверка, что список рук в интерфейсе совпадает со списком в ядре | расхождение — это ложь одной из сторон |
| 19 | Запретить руке появляться в интерфейсе без строки реестра и тест-кейса | инвариант проекта, проверяемый генератором |
| 20 | Отчёт «что приложение делает само, без спроса» — и там должно быть пусто или названо | автономность не должна быть тайной |

| 36 | Устройства ввода: если нет микрофона — предложить текст, а не ошибку | всегда есть путь без голоса |

| 38 | Отказ от знакомства не блокирует работу | никаких обязательных анкет |
| 39 | Проверка, что после первого запуска приложение не спрашивает разрешения повторно | иначе каждый раз — анкета |
| 40 | Журнал первого запуска: что скачано, что проверено, что отложено | видно глазами, а не догадкой |

## 4 · Модели: лучшие для слабого железа и достаточные для сильного

| № | Шаг | Зачем / чем проверяется |

| 62 | Роль → модель, а не «одна на всё»: разговор, планирование, код, распознавание | одна большая модель на слабом ноутбуке даёт 2 ток/с и виджет зависания |

## 5 · Мозг: понимать фразу, а не искать подстроку

| № | Шаг | Зачем / чем проверяется |
| --- | --- | --- |
| 81 | Разбор намерения: глагол+объект, а не совпадение слов | «найди большие файлы» и «найди файл по имени» — разные вещи |

## 6 · План и руки: сто раз одна и та же цепочка

| № | Шаг | Зачем / чем проверяется |
| --- | --- | --- |
| 101 | План показывает цель, шаги, риск и что будет сделано — до запуска | согласие на слепой запуск — это не согласие |

| 115 | План, который нельзя собрать из рук, честно отказывает целиком | не выполнять половину и молчать |
| 116 | Редактирование плана человеком — в понятных полях, не в JSON | JSON — для разработчика |
| 117 | Каждое изменение плана после согласия требует нового согласия | иначе обход |
| 118 | Отчёт по шагу: сделано / не сделано / неизвестно — тремя словами | «неизвестно» — честный статус |
| 119 | Сбой шага не скрывает, что уже сделано до него | иначе откат наугад |
| 120 | Связать отчёт с откатом: что из сделанного можно вернуть прямо здесь | один клик |

## Порядок выполнения

Не по номерам подряд, а по риску и по цене ошибки:

1. **Сначала 1–2 блока** (правда о себе, первый запуск) — потому что человек прощает
   неумение, но не прощает обмана и тупика на входе.
2. **Затем 3 и 7** (голос, задержка) — это то, что замечают каждую секунду.
3. **Затем 5–6 и 9** (понимание, план, безопасность) — то, что отличает оператора от болталки.
4. **Затем 10, 12** (интерфейс, устройства) — без этого «для всех» ложь.
5. **Затем 8, 18** (надёжность, самопроверка) — чтобы не разваливалось.
6. **16, 13, 14** (доставка, доказательства, память) — зрелость.
7. **17, 19–26** (расписания, экран дела, производительность, люди, документация, сборка) —
   рост продукта.

Правило шага: **шаг закрыт, когда есть доказательство** — тест, лог без секретов или
заполненный приёмочный кейс. «Код написан» и «CI зелёный» доказательством не считаются,
как и написано в [`ALPHA-IMPROVEMENT-PLAN.md`](ALPHA-IMPROVEMENT-PLAN.md).
